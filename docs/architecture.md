# 架构概览

CloudNode Rust 由控制面同步、代理运行时、缓存系统、安全策略、证书管理、日志统计和本地监控几部分组成。整体设计目标是让配置下发和请求处理解耦，让请求热路径尽量只读取已经构建好的运行时快照。

## 数据流

典型 HTTP 请求的数据流如下：

1. 客户端连接进入 HTTP/HTTPS/HTTP3 监听器。
2. 运行时根据 Host、SNI、端口和协议选择站点配置。
3. 请求进入 `request_filter`，完成站点开关、访问限制、WAF、重写、跳转、缓存预处理等判断。
4. 命中缓存时直接返回缓存对象。
5. 未命中缓存时选择上游节点或源站，构建 `HttpPeer` 并转发请求。
6. 响应阶段处理缓存写入、响应头策略、内容优化、访问日志和统计上报。

四层流量的数据流更短：

1. TCP、TCP-TLS 或 UDP 监听器接入连接。
2. 根据端口、SNI 或协议标识选择转发规则。
3. 建立上游连接并进行双向转发。
4. 记录 L4 连接、流量和错误统计。

## 模块边界

主要模块：

- `src/main.rs`：CLI、进程管理、运行时启动和后台任务编排。
- `src/proxy.rs`：L7 HTTP 代理主逻辑，处理请求过滤、上游选择、响应过滤、缓存和日志触发。
- `src/http_proxy_manager.rs`：HTTP/HTTPS 监听、TLS 回调、共享 443 入口和 SNI 透传分流。
- `src/http3_proxy_manager.rs`：HTTP/3 入口。
- `src/tcp_proxy.rs`、`src/udp_proxy.rs`：四层代理入口。
- `src/config.rs`：运行时配置存储和热路径快照。
- `src/config_models.rs`：控制面 JSON/PB 配置反序列化模型。
- `src/rpc/`：控制面 RPC 客户端、配置同步、任务同步、日志统计上报。
- `src/cache_hybrid.rs`：Memory + Disk 混合缓存实现。
- `src/firewall/`：WAF 匹配、状态、挑战和拦截逻辑。
- `src/ssl.rs`：动态证书选择和证书更新。
- `src/metrics/`：运行时指标、统计聚合和持久化。
- `src/perf_monitor.rs`：本地性能监控页面。

## 控制面同步

节点通过 `configs/api_node.yaml` 获取 RPC endpoint、`nodeId` 和 `secret`。启动后会连接控制面，完成以下同步：

- 节点基础信息上报。
- 已连接 API 节点上报。
- 全局配置同步。
- 站点配置和端口监听配置同步。
- 证书、缓存任务、WAF 状态和节点任务同步。
- 访问日志、节点日志、统计数据上报。

RPC 客户端使用 gzip 压缩和较大的 message size 限制，适配大配置下发和批量日志上报。

## 热路径快照

请求热路径不应该频繁解析配置或深拷贝大型结构。`ConfigStore` 会为请求构建轻量快照，其中包含：

- Host 到站点的映射。
- 端口监听和 SNI 配置。
- 缓存策略引用。
- 全局开关和访问日志配置。
- 节点层级、父节点和父节点压力信息。

高频读取尽量使用 `Arc`、原子计数和并发结构，降低锁竞争。

## 缓存架构

缓存系统分为三层：

- 请求侧缓存策略匹配，决定是否允许读写缓存。
- `HybridStorage` 负责 Memory + Disk 的读写和淘汰。
- Mace 和内存索引保存缓存元数据，避免命中路径频繁访问持久化存储。

缓存目录默认使用 `data/cache`，也可使用控制面下发的缓存目录。运行时会维护缓存大小、文件数量、磁盘剩余空间和后台清理任务。

响应变体会进入缓存 key 计算。非 GET 请求追加 method 变体，压缩响应追加 encoding 变体，WebP 图片转换追加 `@webp` 变体。WebP 变体只在站点 WebP 规则匹配图片请求时启用，并在上游响应写入缓存前完成转换，避免缓存命中后重复执行图片编码。

## 安全架构

安全能力分为请求前置判断和 WAF 深度判断：

- 前置判断：站点开关、请求限制、IP 限制、地区限制、限速、流量限制、跳转。
- WAF 判断：规则组、规则集、条件匹配、动作执行、挑战页面和封禁状态。
- 状态管理：IP 封禁、CIDR 封禁、挑战状态和本地防火墙联动。

观察模式会把部分阻断动作降级为日志动作，用于灰度验证规则。

## 日志与统计

日志和统计不在请求热路径中同步上传。请求处理阶段只生成事件并投递到通道，后台任务负责批量上传：

- 访问日志批量上传。
- 节点日志批量上传。
- 实时统计、日统计、Top IP、节点值上报。
- 本地性能监控采样。

批量上传失败时会进行有限重试，避免短暂控制面异常导致大量日志立即丢失。
