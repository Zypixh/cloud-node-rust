# cloud-node-rust 1.0.6

本文件记录 `1.0.6` 的发布说明。

## 概述

1.0.6 重点补齐控制面 PB 协议兼容和节点运行时行为，修复真实 API 通信中的上线状态、`nodeStream` 长连接、配置解析应用和部分 Go 时代功能差异。同时继续收敛热路径阻塞、锁竞争和不必要日志输出。

本日志已剔除由开发过程中临时实现、回滚或中间错误引发的修复记录，只保留对最终功能、兼容性、性能和运维有意义的变化。

## 控制面协议兼容

- 修复节点上线状态上报：配置应用成功后立即调用 `updateNodeStatus`，确保控制端能看到节点在线和健康状态。
- 保持 Go 兼容的节点 token 载荷，认证 token 中的 `type` 固定为 `node`。
- 兼容控制面 `nodeId` / `token` metadata，避免不同 gRPC 实现对 metadata 大小写处理差异造成认证失败。
- 增加真实 API 集成测试，覆盖配置拉取、Brotli 解压、PB JSON 解析、配置应用、状态上报和 stream 保持。
- 增加 30-60 秒真实 API 长连接测试窗口，避免只验证瞬时 RPC 成功。

## nodeStream 长连接

- 实现底层 HTTP/2 gRPC frame 版 `nodeStream`，用于明文 HTTP endpoint。
- 请求流打开后立即发送 `ping` 并进入保持状态，不再把“服务端响应头已返回”作为建流成功前置条件，行为更接近 Go 客户端。
- 收到控制端消息后复用统一 `handle_message()` 分发执行动作，并按 `requestId` 回复结果。
- 已支持消息：
  - `connectedAPINode`
  - `newNodeTask` / `NewNodeTask` / `configChanged`
  - `writeCache`
  - `readCache`
  - `statCache`
  - `cleanCache`
  - `getStat`
  - `changeAPINode`
  - `checkSystemdService`
  - `checkLocalFirewall`
- 未识别消息会回复 `unhandled`，不会静默丢弃。

## 功能补齐

- 补齐域名不匹配处理，支持控制面兼容字段和节点 IP 页面配置。
- 补齐 Basic Auth、Referer 防盗链、User-Agent 策略解析和请求侧执行。
- 补齐 rewrite 和 host redirect 兼容能力，包括 redirectStatus、isBreak、proxyHost、递归 rewrite、URL/domain/port redirect、keepArgs 和搜索引擎默认 301。
- 补齐 HSTS、WebSocket Origin 校验、上游 Origin 模板覆盖和条件响应头策略。
- 补齐 Random 回源调度；控制面未显式下发 scheduling 或 code 为空时默认使用 Random。
- 补齐源站失败状态管理，连续失败后临时摘除并在超时后自动恢复探测。
- 补齐 SQLi/XSS 检测操作符的 libinjectionrs 主检测路径，并保留受限正则兜底。
- 补齐本地防火墙检查代码页，当前只做能力检测；暂不启用完整 DDoS/nftables 规则托管。
- 增加暂不支持功能的代码占位页，明确标注暂不考虑自动升级、静态文件服务、请求脚本和 IP 库更新器等能力，避免误判为已实现。
- 增加配置兼容测试，验证控制端下发的兼容字段能正常解析并应用到热路径快照。

## 性能和稳定性

- 修复 `nodeStream` 建立阶段可能永久等待响应头的问题，避免后台 stream 任务卡死。
- 修复 HTTPS 强制跳转默认状态码，未显式配置时使用 `301`。
- 补齐上游标准转发头 `X-Real-IP`、`X-Forwarded-Host`、`X-Forwarded-Proto`。
- 缓存通配符域名和 User-Agent 过滤正则，避免每请求重复编译。
- 将 async 路径中的负载均衡器构建隔离到 blocking 线程，避免同步 DNS 解析阻塞 Tokio worker；运行时 fallback 不再触发同步 DNS 构建。
- 继续减少配置热路径克隆和锁获取，缓存引用、全局配置、WAF actions 和父节点映射改为 Arc 共享，ProxyCTX 大对象改为懒分配。
- WAF SQLi/XSS 检测使用本地 patched libinjectionrs，移除上游 crate 的构建脚本依赖，优化 SQLi fingerprint 和关键词查询热路径。
- 响应头策略、CORS、HSTS、Alt-Svc、X-Cache、WebP 等响应阶段修改后会同步刷新日志/WAF 使用的响应头快照和 header size。
- WebP 转换改为 transformed-cache 语义：只有命中缓存策略且响应允许缓存时才转换，转换结果在写入缓存前生成，后续 WebP 变体命中缓存时不再重复转换。
- WebP 缓存 key 只在站点 WebP 规则匹配当前图片请求时追加 `@webp`，避免 WebP 关闭时生成普通图片的重复缓存变体。
- 优化 L1 快速缓存命中元数据、TLS 证书选择、User-Agent 分析缓存、CC 计数器清理和 cache access 统计写入路径。
- 新增 `targeted_hotspots_bench`，覆盖 Fast L1、WebP/HTML/CSS/JS/AES 响应体 CPU 成本、TLS selector、UA analyzer cache 和 WAF verifier。
- 优化访问日志和节点日志输出，保留关键配置获取、同步和错误信息，减少高并发场景下的杂乱 info 日志。
- 保持日志投递非阻塞，避免控制面异常反压请求热路径。
