# cloud-node-rust 1.1.6

## 概述

1.1.6 聚焦 Go 版本统计上报口径补齐、统计恢复能力、运行时资源治理、缓存/QUIC 入场控制、SNI/AnyTLS passthrough 稳定性、节点自升级能力以及节点时间一致性。该版本补齐 DAU、countIPs、带宽窗口恢复、HTTP 统计 TopN 限制、MetricStat 请求 key 模板和 TCP/UDP 收发字节维度，使节点上报更接近 Go 实现；同时强化内存水位下的缓存、连接和 QUIC admission 行为，修复测速上传等 established tunnel 收尾场景误记 502 和误伤源站健康的问题，新增内置 `upgrade` 与 `ntp` 命令，降低高压场景下的误读、过量分配、时间偏差和运维升级成本。

## 统计上报

- DAU 与 countIPs 统计状态持久化到 RocksDB，节点重启后不再丢失日维度去重状态。
- 带宽统计新增 pending/window 恢复路径，重启后可继续补报未完成窗口。
- HTTP 统计上报接入 `globalServerConfig.stat.upload`，按服务端配置限制每类 TopN 上传规模。
- MetricStat 请求 key 模板对齐 Go 版本口径，减少控制面聚合维度差异。
- TCP 与 UDP 统计补齐 `bytes_received` 维度，收发字节口径更完整。
- 访问日志上传遇到 `ResourceExhausted` 后会丢弃已读请求体再重试，避免背压期间重复持有大对象。

## 运行时与资源治理

- 统一运行时调度资源规划，补齐内存治理文档和运行时说明。
- 共享连接 admission budget，用统一预算约束 L7 源站连接、TCP、UDP 和 QUIC 路径。
- QUIC UDP demux 增加资源 admission 防护，避免高并发握手和连接状态超出预算。
- 内存治理器扩展压力状态、保留量、预算计算和测试覆盖，提升高压场景下的可解释性。
- 性能监控与内存计划同步更新，节点运行时资源视图更贴近实际预算。

## 升级命令

- 新增 `cloud-node upgrade`，可从 GitHub Releases 自动选择当前 CPU/架构匹配的 release 包并升级。
- 支持 `--version` 指定版本，默认升级到 `latest`；支持 `--yes`/`--non-interactive` 用于脚本化非交互升级。
- 支持 `--github-mirror` 和 `--github-base-url`，便于使用 GitHub 镜像、代理站或 GitHub Enterprise。
- 升级前会备份旧二进制，支持 `--dry-run` 预览升级计划和 `--no-restart` 只替换不重启。

## 时间同步与时区

- 新增 `cloud-node ntp` 命令，可交互式设置系统时区并执行一次 NTP 校时；手动执行会在 Linux 上修正系统时钟，非交互模式支持 `--timezone`、`--no-timezone`、`--yes`、`--server` 和 `--timeout-ms`。
- 内置多个全球可用 NTP 源，包括 Cloudflare、Google、pool.ntp.org、Apple、Windows、Ubuntu、Aliyun 和中国区 pool，单个源失败会自动尝试后续源。
- 节点启动后会周期性执行自动 NTP 同步，校准程序内部时间偏移，不主动改系统时钟，避免和系统 chrony/systemd-timesyncd 抢控制权；显式执行 `cloud-node ntp` 才会修改系统时钟。
- 每次自动同步都会上报节点日志：成功时明确记录修正的毫秒级时间偏差和 RTT，未检测到偏差时记录 `no clock offset detected`，失败时记录 warn 节点日志。
- 全新安装脚本 `--fresh` 会询问系统时区；非交互安装可通过 `--timezone Asia/Hong_Kong` 或 `TIMEZONE=...` 指定，也可通过 `--no-timezone` 保持现状。
- 访问日志和运行日志继续使用节点本地时区；SNI/L4 passthrough 访问日志修复了之前固定输出 UTC `+0000` 的问题。
- NTP 内部时间偏移会同步作用于 HTTP/SNI 访问日志时间、节点状态时间戳、带宽/日报/HTTP 统计窗口和 Top IP 统计窗口；HTTP/S3 协议 GMT 头、Kubernetes Lease、NTP 测量和系统资源治理仍保留 UTC/系统时间语义。

## 缓存与内存安全

- 缓存 HIT 读取路径增加内存保护，避免在压力状态下继续扩大内存占用。
- Hybrid cache admission 与 Fast L1 路径按内存预算收敛，降低缓存命中和写入路径的尖峰占用。
- 缓存统计、淘汰和 admission 行为增加测试覆盖，避免压力状态下产生不一致的缓存状态。

## 防火墙与代理路径

- 防火墙匹配与状态路径适配新的资源预算和统计行为。
- HTTP proxy manager、proxy、TCP proxy、UDP proxy 同步接入新的 admission、统计和字节维度。
- RPC stats/node/stream 路径收敛统计上传、节点状态和长流状态处理。
- SNI/AnyTLS passthrough 的 established relay 将 `BrokenPipe`、`ConnectionReset`、`UnexpectedEof`、`ConnectionAborted`、`EPIPE`、`ECONNRESET`、`ENOTCONN` 等收尾错误归类为良性关闭，避免 speedtest.net 上传阶段把正常连接记录为 502。
- TCP relay 保留 Linux `splice` zero-copy 热路径；上传方向良性关闭后仍允许响应方向最多 5 秒 drain，响应方向已断开的情况下上传方向只保留短窗口，避免测速上传等场景产生无意义尾部等待；hard error 仍会强制关闭双端连接。
- SNI passthrough 已成功连接源站后，relay 收尾类错误不再累计源站失败；连接源站失败和 PROXY Protocol 写入/flush 失败仍记录 502 并参与源站健康判定。
- SNI passthrough access log 对 200 状态下的 `benign relay close` 增加方向、阶段、raw OS error 和 drain 耗时，便于定位上传慢是否来自 relay 收尾路径。
- 源站 down 自动恢复时间从 300 秒缩短为 60 秒；单源站场景仍保持 down 只影响优先级、无健康源时 fallback 到该源站。

## 兼容性与行为变化

- 统计数据库会新增 DAU/countIPs 和带宽恢复相关状态；既有数据目录可继续使用。
- HTTP 统计上传会受 `globalServerConfig.stat.upload` 限制影响，控制面未下发时沿用默认行为。
- 高内存压力下缓存、连接和 QUIC admission 会更早拒绝或收缩资源，优先保证节点稳定性。
- SNI/AnyTLS passthrough 的客户端或对端正常收尾 reset 不再计为源站失败；access log 会用 200 和 `benign relay close` / `relay drain timeout after benign close` 注明收尾状态。
- 节点会自动维护程序内部时间偏移；守护进程默认不修改系统时间，只在安装脚本或显式执行 `cloud-node ntp --timezone ...` 时调整系统时区，显式执行 `cloud-node ntp` 时会按 NTP 结果校准系统时钟。
