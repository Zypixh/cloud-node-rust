# cloud-node-rust 1.1.9

## 概述

1.1.9 修复高频 WAF/L4 封禁下 nftables 同步队列饱和、CPU 异常升高和日志风暴问题。问题根因是每次单 IP 封禁都会重新发布完整防火墙快照，并由 nftables worker 为快照中的每个 IP 单独创建 `nft` 子进程；封禁集合增长后，单次请求会产生数千个重复操作。

## 修复内容

- nftables 待处理队列改为按 IP 合并，重复 block/unblock 只保留最新操作，唯一待处理项继续受 8192 上限约束。
- 完整快照改为单次原子 `nft -f -` 事务，统一刷新 IPv4/IPv6 set，不再为每个快照元素启动独立进程。
- 运行期黑名单和 L4/WAF 封禁改为增量同步，避免每次变更扫描并重新发布全部封禁项。
- 队列溢出日志按 10 秒聚合，节点日志携带累计丢弃数和容量，避免 journald 与日志上传形成 CPU/I/O 放大。
- 区分逻辑封禁和需要内核执行的封禁，修复 `use_local_firewall=false` 仍可能被完整快照写入 nftables/XDP 的问题。
- 运行时封禁恢复改为先恢复内存状态、最后同步一次快照，避免启动阶段 O(N²) 同步。
- C 段封禁持久化现在保留真实的 `kernel_wanted` 值，后续重启可恢复一致的内核执行语义。
- L4 聚合前缀封禁统一通过 `block_ip(..., block_c_class=true)` 更新，移除重复状态写入和重复内核同步。
- nftables 新增 IPv4/IPv6 interval set，CIDR 和闭区间地址段现在会进入真实内核封禁；重叠区间按最高有效期拆分为无重叠元素，避免事务因 interval 冲突失败。
- nftables 同步事务同时维护精确 IP、CIDR/range 和白名单 set，白名单规则优先 `return`，只跳过本项目封禁链而不绕过后续主机防火墙。
- iptables fallback 改为 50ms 有界合并队列，IPv4/IPv6 分别通过一次 `iptables-restore`/`ip6tables-restore` 原子重建专用链，不再为每个 IP 创建 Tokio 任务和子进程。
- iptables fallback 补齐 CIDR 与 `iprange` 地址段规则，并在启用时清理旧版本遗留的 `waf_ttl` 直写 INPUT 规则，避免过期封禁永久残留。

## 运维影响

- 不新增配置项，不改变控制面协议和序列化格式。
- nftables 全量同步使用事务方式替换 `cloud_node` 表中的 `blocked_v4` 与 `blocked_v6` set 内容，更新过程保持原子性。
- iptables fallback 会创建并挂载 `CLOUD_NODE` 专用链；TTL 到期项由运行期变更及每 60 秒的完整快照对账清理。
- 未启用本机防火墙的逻辑封禁仍由用户态 WAF/L4 路径执行，不再被意外提升为内核封禁。
