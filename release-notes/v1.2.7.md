# cloud-node-rust 1.2.7

本版本聚焦普通 UDP 直通路径的多核扩展、会话创建并发控制、地址解析开销以及高突发收发调度优化。

## 变更总览

- 普通 UDP listener 使用 REUSEPORT 多 worker，每个 worker 独立接收 socket，提升多核扩展能力并分散客户端回包压力。
- 新增 direct UDP worker budget，并增加 listener generation 保护，避免旧 worker 退出时误删新 listener。
- 同一 `(client_addr, listen_port)` 的并发新会话创建采用 single-flight，避免重复执行路由、准入、负载均衡和 DNS 解析。
- 新增 bounded UDP DNS 成功缓存：成功结果缓存 30 秒，容量上限 4096；按 origin、host、port、地址族和 runtime reload generation 隔离；失败和空结果不缓存。
- `UdpSession.client_addr` 改用 `ArcSwap<SocketAddr>`，完整支持 IPv4/IPv6，并保留队列满/关闭时不更新地址和活动时间的既有语义。
- Linux UDP listener 使用预分配缓冲区的 `recvmmsg` 批量收包，并在非 Linux 平台保留等价的单包 fallback；同时启用 `SO_RXQ_OVFL` 观测内核接收队列溢出。
- backend relay 在一次唤醒后进行有界、顺序保持的批量 drain，最多连续发送 32 个已排队数据报，降低高突发场景下的调度与唤醒开销。
- 增加 UDP listener、DNS single-flight、session creation race、REUSEPORT bind、地址族和内存预算回归测试。

## UDP 会话韧性修复

针对把服务端状态绑定到上游四元组的 UDP 协议（例如按源 IP:port 校验会话、不支持漫游的隧道），本次修订修复了多处会导致"一次 session 重建 = 换上游端口 = 对端静默断流"的问题：

- `handle_session` 不再把瞬时 io 错误当致命错误：backend `send`/`recv` 错误（connected UDP socket 会把 ICMP unreachable 透传为 `ConnectionRefused`）改为丢包后继续，session 保留；downstream `send_to` 的非 `WouldBlock` 错误同样改为丢包，session 不再销毁。backend `send` 错误仍计入 origin `record_failure`（保留死源检测），`connect`/`bind` 失败仍快速失败。
- 新增 upstream 端口复用：session 退出时把 `(client_addr, listen_port) -> backend socket local_addr` 记入 `recent_upstream_ports`（TTL 120s，上限 65,536）；同一 key 重建 session 时先尝试独占绑定原端口（不带 SO_REUSEPORT，避免与通配 bind 共享端口导致回包分流），失败再退回 `:0`。tuple-pinned 协议因此可以在 session 重建后透明续流。
- listener 移除增加宽限期：`UdpProxyManager::reconcile_listeners`、`QuicUdpDemuxManager::reconcile_listeners`/`reconcile_af_xdp_handles` 在端口从期望集合中消失时延迟 10 秒才真正停 listener 并 `remove_sessions_for_port`，避免配置快照瞬时缺失导致整端口 session 团灭；端口重新出现立即清除标记。`http3_enabled` 标志变化仍立即重启（socket 语义不同，不能拖延）。
- `UdpQueueFull` L4 防御事件改为按 session 限频（每条 session 每秒最多计 1 次），普通/demux 两条路径一致，避免大流量合法客户端因队列丢包被快速误封。
- QUIC CID 更新通道改 `try_send`（CID 簿记是机会性的，demux 每次 dispatch 都会从 `session_cids` 重建路由，通道满不再阻塞包路径）；`send_to_session_from_client` 先把数据报入队再做 CID 簿记，permit 不再横跨 await。

## 行为与兼容性

- 保持 `Blocked`、`NoRoute`、`Full`、`Closed`、admission reject 和 downstream `WouldBlock` 语义不变。
- DNS、负载均衡、backend bind/connect 等错误仍向上传递，不回退到旧地址、默认 backend 或空结果。
- 普通 UDP session map 仍使用 `(client_addr, listen_port)`，本版本不新增 rebinding alias。
- session 因瞬时错误不再销毁属于语义强化：依赖"错误即拆 session"的路径需注意上游端口现在可以跨错误保持稳定；`record_failure` 仍按发送错误累计，origin down 判定不变。
- QUIC/H3 demux 端口分类和行为未改变。
- 未在本版本引入 `sendmmsg`、GSO、L4 fast path、接收缓冲区缩减或 QUIC CID 解析优化；socket 缓冲区仍由 memory governor 统一管理，未基于当前本机证据调整预算。

## 验证

- UDP proxy 单元测试：26 项通过（含新增：downstream 错误不拆 session、上行端口复用/回退、queue-full 限频、listener 移除宽限期）
- net_bind 单元测试：3 项通过
- memory governor 单元测试：34 项通过
- memory governance 集成测试：10 项通过
- L4 resilience 集成测试：8 项通过
- library Clippy：通过
- `cargo check --locked --all-targets`：通过
- 本机高突发基线：20,000 次发送中最近一轮观测到 `ingress_received=12,048`、`backend_received=11,994`、`full=0`、`closed=0`；该测试用于本机 A/B 趋势验证，结果受 macOS UDP 栈和调度影响，不作为吞吐承诺。Linux `recvmmsg` 和 `SO_RXQ_OVFL` 仍需 Linux runner 原生验证。
