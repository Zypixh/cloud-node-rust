# cloud-node-rust 1.1.5

## 概述

1.1.5 聚焦特殊攻击防御策略归属、PROXY Protocol 接收能力、Pingora 0.8.1 升级、TLS 后端迁移到 rustls、RocksDB 绑定迁移、Rust 1.96 工具链升级和 RPC 长流稳定性修复。节点加入多个集群时，特殊攻击防御统一以节点主集群配置为准，从集群配置不参与触发、统计或 fallback；系统防火墙封禁仍保持节点级生效。

## 特殊攻击防御

- 明确特殊攻击防御是节点级全局策略，但配置来源只读取节点主集群。
- 空连接泛滥攻击防御只使用节点主集群的 `emptyConnectionFlood` 配置。
- TLS 资源耗尽攻击防御只使用节点主集群的 `tlsExhaustionAttack` 配置。
- CC 攻击基础防御只使用节点主集群的 `httpCCPolicies`，主集群没有配置时才回退到同属主集群 WAF policy 的 `ccConfig`。
- 从集群下发的空连接泛滥、TLS 资源耗尽、CC 基础防御配置全部忽略。
- 如果主集群未启用对应防御，即使从集群启用了，也不触发。
- 如果主集群启用对应防御，则作为节点级全局策略作用于该节点所有站点。
- 防御触发、应用层计数和应用层封禁 scope 均使用主集群 ID，避免按站点所属从集群切换策略。
- 系统防火墙封禁不做集群隔离，`useLocalFirewall=true` 后仍按节点级封禁生效。
- 上报事件保留特殊防御来源信息，并尽量携带主集群 ID，便于排查策略来源。

## 集群归属解析

- `ServerConfig` 新增并保留站点顶层 `clusterId`。
- 站点集群归属只解析控制面真实字段 `clusterId`，不再接收 `nodeClusterId` / `NodeClusterId` 兼容字段。
- 全量配置和 `ComposeServerConfig` 均支持解析站点集群归属。
- 没有 `clusterId` 的站点视为未知集群，不作为从集群策略参与特殊攻击防御。
- WAF policy 仍没有控制面直接下发的 `clusterId`，节点侧通过站点引用关系建立 `policy_id -> cluster_id` 索引。
- 该索引用于判断主集群 WAF policy 的基础防御配置，不再扫描全部 WAF policy。

## 配置字段接收收窄

- 已核对控制面原始配置，项目中的 `serde alias` 已全部移除，节点侧不再通过 serde 接收大小写变体、snake_case、旧字段名或语义近似字段。
- 顶层节点配置只接收真实字段，例如 `servers`、`dataMap`、`httpFirewallPolicies`、`httpCachePolicies`、`sslCerts`、`parentNodes`，不再接收 `Servers`、`data_map`、`HTTPFirewallPolicies`、`SSLCerts`、`ParentNodes` 等旧写法。
- `dataMap` 内部真实字段为 `Map`；`globalServerConfig.httpAll.allowLocalOrigins` 作为真实字段接收，不再接收 `allowLANIP`。
- `toa` 配置按真实字段 `sockPath`、`minLocalPort`、`maxLocalPort` 接收，修正原模型等待 `sockFile`、`minPort`、`maxPort` 导致 TOA 端口范围无法正确解析的问题。
- 站点配置只接收 `clusterId`、`httpFirewallPolicyId`、`httpFirewallPolicy`、`reverseProxy`、`grpc`、`serverNames`、`isOn` 等真实字段，不再接收 `nodeClusterId`、`firewallPolicyId`、大写模块名或 `reverseProxyConfig`。
- HTTP/HTTPS/TCP/UDP 监听配置只接收 `isOn`、`listen`、`sslPolicy`、`http3Enabled`；不再接收 `IsOn`、`Listen`、`SSLPolicy`、`supportsHTTP3`、`enableHTTP3`。
- Web 子配置按真实字段 `webp`、`userAgent`、`referers` 接收，不再接收 `webP`、`userAgentConfig`、`refererConfig`。
- URL 范围规则只接收 `onlyURLPatterns` / `exceptURLPatterns`，单条规则只接收 `type` / `pattern`，不再接收 `onlyUrlPatterns`、`limitURLPatterns`、`exceptUrlPatterns`、`patternType`、`matchType`、`value`、`url` 等兼容写法。
- WAF 配置按真实字段 `captchaType`、`life`、`failBlockScopeAll`、`countLetters`、`lang`、`status`、`body` 接收；`blockOptions` 仍按真实字段 `statusCode` 接收。
- `domainMismatchAction.options` 是原始 options 对象，控制面真实字段仍为 `statusCode` / `contentHTML`，因此该 raw options 读取保持不变。
- Rewrite 规则只接收 `pattern`、`replace`、`withQuery`，不再接收 `match`、`source`、`from`、`targetURL`、`target`、`to`、`keepArgs`、`keepQuery`。
- 证书配置只接收 `certData` / `keyData`，不再接收 `certDataJSON` / `keyDataJSON`。
- 源站配置只接收 `addr`、`healthCheck`、`requestHost`、`http3Enabled`，不再接收 `address`、`Addr`、`HealthCheck`、`host`、`supportsHTTP3`、`enableHTTP3`。
- `reverseProxy.proxyProtocol` 只接收控制面真实对象 `{ "isOn": bool, "version": 1|2 }` 或 `null`，不再接收字符串、数字、`proxy_protocol`、`enableProxyProtocol` 等兼容写法。
- OSS 源站的 `LooseOssConfig` 同步移除 `serde alias`；OSS provider raw `options` 仍保留 provider 专属 key 探测，因为当前控制面样本没有启用 OSS 源站，不能将 provider 专属字段误判为统一旧字段。
- 内部集群 purge API 只接收 `key_type`，不再通过 serde 接收 `keyType`。
- 保留 `deserialize_null_default` 处理控制面真实 `null` 的能力；这不是旧字段名兼容，而是防止真实空值使配置解析失败。

## PROXY Protocol

- 明确区分接收客户端 PROXY Protocol 与向源站发送 PROXY Protocol。
- 新增节点侧接收 PROXY Protocol 能力。
- 支持按站点配置解析 PROXY Protocol v1。
- 支持按站点配置解析 PROXY Protocol v2。
- HTTP/HTTPS 和 TCP/TLS 入口均在业务协议解析或 TLS 握手前消费 PROXY Protocol 头。
- 保留向源站发送 PROXY Protocol 的既有能力。
- 增加配置解析测试，验证 v1/v2 配置可正常下发和识别。

## TLS / rustls

- TLS 后端从 Pingora BoringSSL/OpenSSL 切换为 `pingora-rustls`。
- 根项目 `pingora` 依赖启用 `rustls` feature，直接依赖的 `pingora-core`、`pingora-proxy`、`pingora-cache`、`pingora-load-balancing` 也显式启用 `rustls` feature。
- 动态证书选择迁移到 rustls `ResolvesServerCert`。
- 保留 SNI 精确匹配、泛域名匹配、默认证书选择和 OCSP 更新。
- HTTP/3 复用统一动态证书选择器，减少 HTTP/1.1、HTTP/2、HTTP/3 证书路径差异。
- HTTP/HTTPS downstream 使用 rustls acceptor，并通过 ALPN 区分 HTTP/2 与 HTTP/1.1。
- TCP TLS downstream 使用 rustls acceptor。
- TCP TLS upstream 使用 rustls client config。
- TCP 通用 TLS 默认不广告 HTTP ALPN，避免 L4 TCP-TLS 被误协商成 HTTP 协议。
- 修复 L7 upstream 在 `verify_origin_tls=false` 且没有 ALPN、自定义 CA 或客户端证书时，rustls connector 仍可能执行证书校验的问题。
- rustls 仅支持 TLS 1.2 / TLS 1.3，TLS 1.0 / TLS 1.1 不再支持。

## Pingora 0.8.1

- Pingora 全量升级到 0.8.1。
- 同步 vendored Pingora workspace 中各 crate 版本。
- 适配 Pingora rustls listener，从已有 `rustls::ServerConfig` 构造 acceptor。
- 收敛 `rustls-native-certs` 版本，减少重复依赖。
- 将 `openssl-probe` 限定到 OpenSSL/BoringSSL feature 路径，避免 rustls 构建无条件引入 OpenSSL 探测依赖。
- 当前主项目依赖图不再使用 `pingora-openssl`、`pingora-boringssl` 或 `openssl` TLS 后端。

## RocksDB 与存储绑定

- RocksDB Rust 绑定从 `rocksdb` 迁移到 `rust-rocksdb = 0.50.0`。
- 开启 `lz4` 与 `jemalloc` feature，保持缓存和指标元数据路径的压缩能力，并改善高并发写入场景下的 allocator 行为。
- `metrics/storage` 等 RocksDB 使用点已切换到 `rust_rocksdb` API。
- 保持现有 DB 目录、列族语义、merge operator、iterator 和 batch 写入行为不变。

## Rust 1.96 与依赖升级

- 项目 `rust-version` 升级到 `1.96.0`，并新增 `rust-toolchain.toml` 固定工具链。
- 直接依赖移除 `once_cell` 和 `lazy_static`，运行时全局初始化迁移到标准库 `LazyLock` / `OnceLock`。
- QUIC CRYPTO 分片重组路径使用 `core::range::Range` 表示已接收范围，减少对旧 `std::ops::Range` 的依赖。
- 单元测试中的 `assert!(matches!(...))` / `debug_assert!(matches!(...))` 迁移到 `std::assert_matches!`，失败输出更明确。
- benchmark 中的 `black_box` 迁移到 `std::hint::black_box`，减少对 Criterion re-export 的依赖。
- `build.rs` 切换到 `tonic-prost-build`，配套升级 `prost` / `tonic` / `tonic-prost` 到 0.14 系列。
- `reqwest` 升级到 0.13 系列并继续使用 rustls TLS 栈。
- `sysinfo`、`governor`、`maxminddb`、`lru`、`criterion`、`brotli`、`aes`、`cfb-mode`、`md5` 等依赖同步到当前可用版本。
- 访问日志上传默认并发测试改为验证容量不变量，避免在不同 CPU 并发环境下因固定数值产生误判。

## RPC 长流稳定性

- 修复 `nodeStream` 每隔数分钟出现 `BrokenPipe` / transport close 后重连的问题。
- 明确根因是节点侧 gRPC channel 对所有 RPC 统一配置了 60 秒 HTTP/2 keepalive PING，并且 `keep_alive_while_idle=true`，容易触发 Go gRPC 控制面的 keepalive enforcement。
- 新增 RPC 连接 profile，普通短 RPC 使用保守的 10 分钟 HTTP/2 keepalive，`nodeStream` 使用专用 channel profile。
- `nodeStream` 和 `probe_node_stream` 禁用 HTTP/2 keepalive PING，只保留 TCP keepalive 与既有 `NodeStreamMessage { code: "ping" }` 业务心跳。
- `ping_endpoint` 作为短探测请求不再发送 HTTP/2 keepalive PING。
- 保持认证 metadata、业务心跳、endpoint 变更检测和重连 backoff 行为不变，降低修复影响面。

## 缓存与 Set-Cookie

- 已核对控制面原始配置，确认缓存策略字段为 `httpCachePolicies[].cacheRefs[].skipSetCookie`，类型为 JSON bool。
- `skipSetCookie` 节点侧解析收窄为只认控制面真实字段 `skipSetCookie`，不再接受字符串、数字或其它兼容写法；字段缺失时仍按控制台默认勾选处理。
- 缓存配置接收字段收窄为控制面真实字段：顶层只认 `httpCachePolicies`，缓存规则 URL 范围只认 `onlyURLPatterns` / `exceptURLPatterns`，不再接受 `HTTPCachePolicies`、`onlyUrlPatterns`、`limitURLPatterns`、`limitURLs`、`only_urls`、`exceptUrlPatterns`、`exceptURLs`、`exceptionURLPatterns`、`except_urls`。
- 修复 `skipSetCookie=false` 时带 `Set-Cookie` 响应仍被策略层拒绝的测试覆盖缺口，确保 legacy 与 compiled cache policy 判定一致允许缓存。
- 允许缓存带 `Set-Cookie` 的响应内容时，缓存元数据和命中响应仍会剥离 `Set-Cookie`，避免把源站用户 Cookie 重放给其它客户端。
- 统一普通缓存、磁盘缓存元数据更新和分片缓存的响应头存储过滤，剥离 `Set-Cookie`、`Content-Length`、`Content-Range` 以及 hop-by-hop headers。
- 保持 `Cache-Control` 跳过规则、状态码、方法、大小、条件匹配、`Vary: *` 等缓存规则独立生效；取消 `skipSetCookie` 不会绕过这些规则。

## 兼容性与行为变化

- 特殊攻击防御不再按站点所属集群或 SNI/Host 动态切换策略。
- 从集群基础防御配置不再影响节点。
- 随机 SNI、无 SNI、无 Host、共享端口等无法可靠归属站点的攻击流量，仍按主集群特殊攻击防御策略处理。
- 系统防火墙封禁仍可能影响节点上的所有集群和站点。
- TLS 1.0 / TLS 1.1 客户端和源站不再兼容。
- 依赖 OpenSSL/BoringSSL 专属 TLS callback 的后续能力需要迁移到 rustls resolver 或 verifier 模型。
- Rust 1.96 成为最低构建版本；旧工具链不再保证可编译。
- `rust-rocksdb` 仍链接 RocksDB C++ 实现，构建和 release 缓存空间占用仍会明显高于纯 Rust 依赖。
- `skipSetCookie` 不再做兼容字段解析，只接受 JSON bool；如果控制面未下发 `false`，节点会继续按默认开启处理。
- 配置接收模型不再做旧字段名兼容；控制面未下发真实字段时，节点按缺省值或空配置处理。

## WAF 验证挑战增强

- **slider（拼图滑块）**：拼图块形状从随机多边形升级为真实榫卯（凸 tab + 凹 notch），随机边、随机位置；背景从纯渐变升级为分层风景场景（天空、山脉、草地、太阳）；拖动时目标缺口发光提示（30px 感应），放开后 fetch 验证 + 行内重试（无页面跳转），验证通过播放 snap 动画；`verify_trace` 强化：最少 8 个轨迹点、速度变化检测（≥2 相邻段差 >15%）、微修正检测（防止程序化直线拖动）。
- **click（点击验证）**：画布背景升级为暮色天空（渐变、星星、月亮、山脉剪影、地面）；目标字每次随机颜色变体（5 种红色系）、随机字体族（4 种）、随机字号（32–44px）、多层叠加渲染（描边→主色→高光+外发光）；干扰字随机字体/大小/透明度（28–60%），30% 概率镜像翻转；额外 7 个极淡鬼魂字符迷惑 OCR；正确点击径向绿色涟漪 + canvas 辉光，错误点击三段式 shake 动画；全部改为 fetch 行内验证。
- **captcha（图形验证码）**：验证失败改为 fetch 行内重试，自动刷新画布并清空输入，不跳转页面；输入框实时强制大写 + 过滤非法字符 + 显示"还需 N 个字符"倒计数；支持 Enter 提交。
- **jscookie**：各步骤完成后 label 前缀"✓"；提交状态显示实际耗时（秒）；`crypto.subtle` 不可用时在状态区插入"重试"链接，不再显示死错误。
- **共享**：新增 i18n 键（`slider_verifying/retry/near`、`click_wrong/verifying`、`captcha_wrong/verifying/refreshed`）；`shared_css()` 补充 `.clk-ok` 和 `@keyframes capFocus`。

## 性能优化

- `normalize_event_level_str` 返回类型从 `Option<String>` 改为 `Option<&'static str>`，消除每次 WAF 规则匹配时的堆分配；`normalize_event_level_value` 同步更新，整数等级码改为静态 match，不再调用 `format!()`。
- `captcha_options_from_value` 和 `js_cookie_options_from_value` 改为 `Value::to_string` + `serde_json::from_str`，避免对 `serde_json::Value` 树做完整 `.clone()` 再传入 `from_value`。
- `cargo check` 零错误零警告。

## 已知事项

- `pingora-main` workspace 仍保留 OpenSSL/BoringSSL/S2N 后端源码和 crate，用于 vendored Pingora 的可选后端；主项目当前依赖图没有启用这些 TLS 后端。
- `rustls-native-certs` 可能在跨平台依赖树中显示 `openssl-probe`，这是系统根证书路径探测依赖，不代表 TLS 后端回到 OpenSSL。
- PROXY Protocol v2 超长 TLV 或慢分片场景仍建议后续补充集成测试。
- `once_cell` / `lazy_static` 已不再作为项目直接依赖，但部分第三方库仍可能传递引入。
- `rust-rocksdb` 的底层 C++ RocksDB 编译体积和构建时间仍然较高；后续若切换到 mace，需要单独做数据格式、崩溃恢复和长期压测验证。
