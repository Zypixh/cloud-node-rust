# cloud-node-rust 1.1.8

## 概述

1.1.8 是 XDP/AF_XDP 数据面首个完整候选版本。该版本在保持默认关闭、可回退到原 socket/Pingora/Tokio 路径的前提下，引入 Linux-only XDP protect/proxy 能力：XDP eBPF 程序在网卡入口执行 allow/block/proxy 决策，AF_XDP 将命中代理端口和队列的流量送入用户态，用户态继续复用现有 HTTP、HTTPS、L4 TCP、UDP、SNI、QUIC 和 HTTP/3 路由、防护、指标与 reload 逻辑。

本版本同时补齐 XDP 运行配置、CLI 诊断、netns smoke 测试、节点状态上报、L4/SYN pressure 观测，以及 x64/arm64 Release 构建链路。1.1.8 不改变默认部署行为：未显式启用 XDP 时，现有监听器、路由和防护路径保持原样。

## 补发更新：XDP 自动接管与 L4 fallback

- `cloud-node xdp start` 现在会自动派生 effective XDP 配置并写入 `configs/runtime.yaml`：接口、队列和业务入口端口由本机路由、网卡队列和 live node server listen 配置自动探测。
- `cloud-node xdp stop` 会关闭 runtime config 中的 `xdp.enabled` 并执行 detach；旧的 `attach`/`detach` 命令保留为 `start`/`stop` 兼容别名。
- `cloud-node xdp configure` 改为自动配置预览/保存，不再要求用户手工选择 attach mode、fallback、interface、queue、local IP、frame size 或 proxy port。
- 自动生成配置固定为 proxy takeover 语义：`attachMode=auto`、`fallback=fail-start`、接口模式为 `proxy`，默认不启用 local IP filter，proxy ports 覆盖当前启用业务监听端口。
- XDP proxy readiness 现在要求所有配置的 proxy interface/queue 都完成 XSK socket 和 redirect readiness，避免多队列或多接口半接管。
- 运行时 XDP attach、map sync、XSK 或 redirect 连续异常时，L4 kernel enforcement 会自动切换到非 XDP 后端（nftables -> iptables -> noop），并重新发布当前 WAF snapshot。

## 补发更新：upgrade 安装 XDP 对象路径

- `cloud-node upgrade` 现在会优先使用当前 `CLOUD_NODE_HOME`、`cloud-node.service` 的 `Environment=CLOUD_NODE_HOME`、`WorkingDirectory`、`/usr/bin/cloud-node` wrapper 的 `cd` 目录，以及当前 runtime 目录来定位运行根目录，再安装 `data/cloud-node-xdp-ebpf.o`。
- 该补发修复了 `/usr/bin/cloud-node` wrapper 场景下 `.o` 可能被安装到 `/usr/bin/data/cloud-node-xdp-ebpf.o`、而运行时实际从 `<runtime>/data/cloud-node-xdp-ebpf.o` 查找的问题。
- 启动时如果 `<runtime>/data/cloud-node-xdp-ebpf.o` 缺失，进程会尝试从当前二进制目录的 `data/`、`/usr/bin/data/` 或当前工作目录的 `data/` 复制误装对象；找不到时只记录 warning，不联网下载，也不阻断普通 socket 数据面。
- 如果机器已经从 `v1.1.7` 或更早版本执行过内置 `cloud-node upgrade`，旧升级器本身只会替换二进制、不会提取 `.o`；这类机器需要重新执行安装脚本，或下载补发后的 release tarball 并把 `data/cloud-node-xdp-ebpf.o` 解包到 runtime `data/` 目录。

## 补发更新：XDP 网卡自动调优与端口同步

- `cloud-node xdp start` 新增无配置启动增强：默认自动检测接口、自动从 live node server listen 配置重算全部 proxy 端口、覆盖 `xdp.proxy.ports`，新增/删除业务端口不再沿用旧 runtime 端口。
- `cloud-node xdp start` 支持 `--interface`、`--mode proxy|protect|observe`、`--attach-mode auto|drv|skb`、`--fallback pass|fail-start`、`--dry-run`、`--no-tune`、`--no-install-tools`；不指定参数时使用自动探测和 aggressive 调优。
- 新增 `cloud-node xdp tune`，可预览或应用网卡调优；`xdp start` 会自动检测 `ethtool`，root 下可通过 `apt-get`、`dnf`、`yum`、`zypper` 或 `apk` 安装缺失工具，服务 daemon 启动时只诊断不上锁安装包管理器。
- XDP 启动前会调优并审计网卡特性、channels、rings、coalesce、link up、`txqueuelen`、RPS/XPS、IRQ affinity 和关键 sysctl；MTU 只检测上报，不默认修改，避免远端网络中断。
- 对 `hv_netvsc` 网卡会明确诊断 `large-receive-offload=on` 阻塞 XDP 的问题，并将 LRO/GRO/GSO/TSO 等 offload 目标值写入调优报告；这修复了 `bpf_link_create` 返回 `Operation not supported` 的典型 Hyper-V/云主机场景。
- 所有调优项都会输出调整前、目标值、调整后、状态、原因和命令，并保存到 `data/xdp-netdev-tuning.json`；服务日志与节点日志使用 `xdp_tuning` tag 上报，端口同步使用 `xdp_ports` tag。
- cloud-node 服务启动时若 `xdp.enabled=true` 会自动执行调优和队列刷新；`fallback=fail-start` 时关键调优失败会阻止启动，`fallback=pass` 时会记录 warning 并回落原 socket 数据面。
- 服务运行期每 30 秒从 live node config 重算 `xdp.proxy.ports`，端口集合变化时写回 `configs/runtime.yaml` 并调用 XDP reload，实现业务监听端口自动添加/删除。
- `cloud-node xdp status` 和 `cloud-node xdp doctor` 会显示最近一次 netdev tuning 概要、`ethtool` 可用性、报告路径以及 `hv_netvsc + LRO=on` 等关键阻塞项。

## 补发更新：AF_XDP L4 抗攻击稳定性

- AF_XDP TCP reactor 现在只为有明确 HTTP/HTTPS/TCP/SNI handler 的初始 SYN 创建会话；未知端口或未知非 SYN 流量不会再增长用户态会话状态，降低异常抓包攻击导致进程假死的风险。
- TCP/HTTP L4 防御状态接入 AF_XDP 路径：已被 L4/WAF 判定封禁的来源会在 AF_XDP reactor 中即时 abort，并按现有 L4 防御事件路径记录压力和封禁原因。
- 代理任务改为在连接达到可代理条件后再启动；TLS/HTTPS/HTTP 会等待客户端首包，慢速首包会按当前 L4 pressure 使用更短 timeout 并记录 `TlsSlowClientHello`、`HttpSlowHeader` 或 `TcpSlowFirstByte` 事件。
- AF_XDP 会话容量改为根据 memory governor 的连接预算计算，并限制在安全上下限；容量耗尽时会记录 SYN backlog pressure，而不是无限接收新会话。
- 修复 AF_XDP proxy bridge 在空闲或半开 TCP 会话下高频调用 memory governor，反复扫描 `/proc/self/fd`、cgroup 和 CPU parallelism，导致单核 CPU 100% 的问题；L4 pressure 和 idle timeout 现在会缓存，空会话直接跳过。
- memory governor 的 FD 数量、FD soft limit、CPU parallelism 和 memory/cgroup 快照进入热路径缓存；AF_XDP/L4 pressure 查询不再在 idle loop 中重复执行 `/proc/self/fd`、`/proc/self/cgroup`、`cpu.max` 或 `getrlimit` 读取。
- AF_XDP XSK 内核统计刷新改为 1 秒节流，`cloud-node xdp status`/doctor 仍会强制刷新，避免空闲 5ms poll loop 反复执行状态查询 syscall。
- `cloud-node xdp stop`、服务启动发现 `xdp.enabled=false`、以及 CLI status 现在会写入 disabled/detached 状态快照；旧 `xdp-state.json` 中的 attached=true 不会再覆盖当前 runtime disabled 语义。
- 增加 ECN SYN 识别、Ethernet 帧级 TCP flags 预过滤和本地 `1.pcap`、`2.pcap`、`443.pcap` 攻击样本解析测试，验证异常流量不会造成 reactor 会话增长。

## XDP/AF_XDP 数据面

- 新增 Linux-only、默认关闭的 XDP/AF_XDP protect/proxy 数据面。
- 新增 `configs/runtime.yaml` 的 `xdp` 配置段，支持 `enabled`、`attachMode`、`fallback`、接口、队列、模式、本机 IP 过滤、frame size、proxy 协议和端口配置。
- 新增 Aya eBPF XDP 程序和共享 map 类型，覆盖 IPv4/IPv6、TCP/UDP、exact allow/block、LPM、range、proxy port、local IP、XSK map 和 counters。
- 新增 `cargo xtask build-ebpf`，将 eBPF 对象构建到 `data/cloud-node-xdp-ebpf.o`。
- proxy 模式仅 redirect 命中端口、命中协议且 XSK ready 的流量；未命中、队列未就绪或降级时继续走原 socket 路径。

## 协议旁路

- AF_XDP TCP stream 接入现有 HTTP/HTTPS 代理入口，保留原路由、TLS/SNI、PROXY protocol、缓存和 L4 防护行为。
- AF_XDP TCP proxy 支持 L4 TCP 和 SNI 透传，复用现有 relay、连接防护和 upstream 选择逻辑。
- AF_XDP UDP datagram 接入现有 UDP session、队列、防护和指标路径。
- QUIC/H3 datagram 进入共享 QUIC demux，复用 H3 manager、CID route、pending-route 防护和 `@quic` 透传逻辑。
- reload 时对接口、队列和 proxy 端口未变化的 AF_XDP bridge 做保留，避免重复绑定队列造成短暂中断。

## 防护与状态

- `kernelFirewallMode` 支持 `xdp`；`auto` 在本机 XDP 配置启用且 attach 成功时优先使用 XDP filter，否则保持原 nftables/iptables/noop 回退。
- `KernelFilter` 扩展 block network、range、snapshot sync 和 status 能力；XDP 后端同步 IP、CIDR、range 和 allow 覆盖。
- 白名单优先级高于封禁；运行时 WAF/IP list 快照通过 XDP shadow maps 同步，过期条目由用户态 sweeper 清理。
- 新增 L4 连接注册，封禁命中后可 drain 相关 L4 连接，减少已封禁来源继续占用连接资源。
- 新增 SYN pressure 观测和 SYNPROXY 管理支撑；`cloud-node defense status` 与 `cloud-node defense synproxy status|enable|disable` 可用于查看或请求本机 SYNPROXY 状态。
- 节点状态上报新增 `xdp` JSON，包含 attach、fallback、proxy、XSK queue、map、counter 和数据面 readiness 状态。

## 兼容性与升级注意

- XDP 默认不启用，现有部署不需要修改配置即可维持原行为。
- 非 Linux 平台保留原行为；XDP 命令会报告不可用或 unsupported。
- 启用 XDP 需要 root，或至少具备 `CAP_BPF`、`CAP_NET_ADMIN`、`CAP_NET_RAW`。
- `cloud-node xdp start` 默认自动选择可用网卡、队列和业务 proxy 端口；生产环境也可以通过 `--interface` 或 `configs/runtime.yaml` 固定网卡。
- 默认 `fallback: pass`，attach、XSK、map sync 或 proxy 降级失败时 fail-open 到原 socket 数据面；需要 fail-closed 时显式配置 `fallback: fail-start`。
- 当前主要验收目标是标准 MTU；jumbo/multi-buffer 场景启用前应先使用 `cloud-node xdp doctor` 检查。
- proxy 模式命中端口后内核 socket 不再收到该包；未命中、降级或 detach 后原监听器继续承载流量。
