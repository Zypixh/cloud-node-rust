# cloud-node-rust 1.1.8

## 概述

1.1.8 是 XDP/AF_XDP 数据面首个完整候选版本。该版本在保持默认关闭、可回退到原 socket/Pingora/Tokio 路径的前提下，引入 Linux-only XDP protect/proxy 能力：XDP eBPF 程序在网卡入口执行 allow/block/proxy 决策，AF_XDP 将命中代理端口和队列的流量送入用户态，用户态继续复用现有 HTTP、HTTPS、L4 TCP、UDP、SNI、QUIC 和 HTTP/3 路由、防护、指标与 reload 逻辑。

本版本同时补齐 XDP 运行配置、CLI 诊断、netns smoke 测试、节点状态上报、L4/SYN pressure 观测，以及 x64/arm64 Release 构建链路。1.1.8 不改变默认部署行为：未显式启用 XDP 时，现有监听器、路由和防护路径保持原样。

## XDP/AF_XDP 数据面

- 新增 Linux-only、默认关闭的 XDP/AF_XDP protect/proxy 数据面。
- 新增 `configs/runtime.yaml` 的 `xdp` 配置段，支持 `enabled`、`attachMode`、`fallback`、接口、队列、模式、本机 IP 过滤、frame size、proxy 协议和端口配置。
- 新增 Aya eBPF XDP 程序和共享 map 类型，覆盖 IPv4/IPv6、TCP/UDP、exact allow/block、LPM、range、proxy port、local IP、XSK map 和 counters。
- 新增 `cargo xtask build-ebpf`，将 eBPF 对象构建到 `data/cloud-node-xdp-ebpf.o`。
- proxy 模式仅 redirect 命中端口、命中协议且 XSK ready 的流量；未命中、队列未就绪或降级时继续走原 socket 路径。

## 协议旁路

- AF_XDP TCP stream 接入现有 HTTP/HTTPS 代理入口，保留原路由、TLS/SNI、PROXY protocol、缓存和 L4 防护行为。
- AF_XDP TCP proxy 支持 L4 TCP 和 SNI 透传，复用现有 relay、连接防护和 upstream 选择逻辑。
- AF_XDP UDP datagram 接入现有 UDP session、队列、防护和指标路径。
- QUIC/H3 datagram 进入共享 QUIC demux，复用 H3 manager、CID route、pending-route 防护和 `@quic` 透传逻辑。
- reload 时对接口、队列和 proxy 端口未变化的 AF_XDP bridge 做保留，避免重复绑定队列造成短暂中断。

## 防护与状态

- `kernelFirewallMode` 支持 `xdp`；`auto` 在本机 XDP 配置启用且 attach 成功时优先使用 XDP filter，否则保持原 nftables/iptables/noop 回退。
- `KernelFilter` 扩展 block network、range、snapshot sync 和 status 能力；XDP 后端同步 IP、CIDR、range 和 allow 覆盖。
- 白名单优先级高于封禁；运行时 WAF/IP list 快照通过 XDP shadow maps 同步，过期条目由用户态 sweeper 清理。
- 新增 L4 连接注册，封禁命中后可 drain 相关 L4 连接，减少已封禁来源继续占用连接资源。
- 新增 SYN pressure 观测和 SYNPROXY 管理支撑；`cloud-node defense status` 与 `cloud-node defense synproxy status|enable|disable` 可用于查看或请求本机 SYNPROXY 状态。
- 节点状态上报新增 `xdp` JSON，包含 attach、fallback、proxy、XSK queue、map、counter 和数据面 readiness 状态。

- 补发更新：新增全局 `--lang en|zh` 语言选项和 `CLOUD_NODE_LANG`/系统 locale 检测，常用管理 CLI 输出支持中文与英文。
- 补发更新：新增 `cloud-node xdp configure` 交互式配置菜单，可写入 `configs/runtime.yaml` 的 XDP 启用状态、attach/fallback、接口、队列、本机 IP、frame size 和 proxy 端口。
- 新增 `cloud-node xdp status`：输出当前或最近持久化 XDP 状态。
- 新增 `cloud-node xdp doctor`：检查本机 runtime 配置、对象文件、接口、队列、proxy 端口和降级风险。
- 新增 `cloud-node xdp attach|detach|reload`：按 `configs/runtime.yaml` 管理当前进程负责的 XDP attach。
- 新增 `cloud-node xdp dump-maps`：输出 XDP shadow maps、proxy port 和 local IP filter 状态。
- 新增 `cloud-node xdp raw-smoke`、`proxy-smoke`、`proxy-reload-smoke`，用于短时验证 raw AF_XDP redirect、协议 proxy 和 reload 保活。
- 新增 `scripts/xdp-netns-smoke.sh`，在 Linux root/netns 环境覆盖 veth attach、allow/block、raw AF_XDP redirect、HTTP/HTTPS/TCP/UDP/SNI/QUIC/H3 proxy、reload 和 detach。

## 兼容性与升级注意

- XDP 默认不启用，现有部署不需要修改配置即可维持原行为。
- 非 Linux 平台保留原行为；XDP 命令会报告不可用或 unsupported。
- 启用 XDP 需要 root，或至少具备 `CAP_BPF`、`CAP_NET_ADMIN`、`CAP_NET_RAW`。
- XDP 不自动选择网卡；生产启用前需要在 `configs/runtime.yaml` 明确接口、队列、模式、本机 IP 和 proxy 端口。
- 默认 `fallback: pass`，attach、XSK、map sync 或 proxy 降级失败时 fail-open 到原 socket 数据面；需要 fail-closed 时显式配置 `fallback: fail-start`。
- 当前主要验收目标是标准 MTU；jumbo/multi-buffer 场景启用前应先使用 `cloud-node xdp doctor` 检查。
- proxy 模式命中端口后内核 socket 不再收到该包；未命中、降级或 detach 后原监听器继续承载流量。
