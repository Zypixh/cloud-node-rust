# cloud-node-rust 1.2.4

## Connection lifecycle and CLOSE-WAIT management

- TCP, SNI passthrough, and AF_XDP relays now use strict-close: an EOF, cancellation, or L4 defense drain in either direction ends the bidirectional relay immediately.
- SNI relays use independent memory admission and release the former HTTP connection permit when the request switches to SNI.
- Under High and Critical memory pressure, the oldest SNI relays are cancelled with a bounded drain to prevent long-lived relay accumulation.
- Relay TCP socket and copy buffers are reduced according to memory pressure, limiting kernel and user-space buffer growth during speed tests and slow upstreams.
- Relay close results, pressure drains, and SNI admission outcomes are exposed through diagnostics.

## Config synchronization and cache writes

- Includes the 1.2.3 low-memory config-sync implementation: streamed parsing, shared ServerConfig Arcs, and pressure-aware staged runtime replacement.
- Cache metadata disk writes are offloaded from request hot paths to a dedicated async writer.

## Upgrade notes

- strict-close deliberately interrupts an incomplete half-closed direction after the peer closes. This prevents CLOSE-WAIT accumulation; nonstandard upstreams that rely on continuing a TCP half-close must be adjusted.
- No data format changes.
