# cloud-node-rust 1.1.2

本文件记录 `1.1.2` 的发布说明。

## 概述

1.1.2 是一次 WAF 正确性、HTTP/3 可用性、RKE2 集群部署和热路径性能更新。重点修复内置 WAF preset 入站漏匹配、缓存命中绕过 WAF、请求体 WAF 在 chunked/无 Content-Length 下失效、IP 名单同步版本推进错误，并补齐 RKE2 多副本部署所需的内部服务、Leader 选举、Longhorn 缓存分片和健康探针。

## WAF 正确性

- 修复 legacy 和 compiled 两条入站路径跳过内置 preset group 的问题，`sqlInjection`、`sqlInjectionStrict`、`xss`、`xssStrict`、`cmdInjection` 现在都会参与入站检测。
- 修复 preset-only 策略未标记 request body 依赖的问题，compiled WAF 会在需要时读取请求体。
- 移除缓存配置下将 WAF 推迟到 cache miss 的逻辑，避免 cache hit 请求绕过 WAF。
- 请求体 WAF 缓冲支持 chunked 和无 `Content-Length` 的请求；超过可检查上限时按 WAF 413 动作处理，不再让 body 规则在空 body 上失败放行。
- WAF 模式语义明确：`defense` 执行动作，`observe` 只记录不执行动作，`bypass` 跳过规则。
- 区域封禁补齐国家、省份、仅允许、仅封禁、例外 URL、限制 URL、自定义 HTML、集群默认 HTML 和搜索引擎放行语义；省份限制仅对中国大陆省份生效。
- WAF 动作支持按控制面顺序组合执行，不限制 action 类型组合；记录白名单、黑名单、灰名单均可按 action 上报。
- `block` 恢复为本地封禁语义；如需同步到控制面名单，应显式配置记录 IP 名单 action。

## IP 名单同步和上报

- 黑名单用于阻止请求；白名单在启用 WAF 时短路放行；灰名单只给访问日志打 tag，不作为 WAF 匹配条件，也不阻止或放行。
- 支持全局/集群黑白灰名单和站级黑白灰名单，WAF action 优先使用控制面下发的 `ipListId`，没有显式名单 ID 时才按 scope/type 解析或创建。
- 修复 IP item 增量同步遇到无法应用的项目仍推进版本的问题；现在只有全部项目成功应用才更新本地版本，避免永久漏同步。
- IP list metadata 同步兼容节点凭据不支持名单类型接口的情况，并避免重复刷屏日志。
- scoped network 匹配改为不可变快照发布，请求路径不再读锁扫描全局 map，降低大量 CIDR 下的锁竞争。

## HTTP/3 和 QUIC

- 支持全局 HTTP/3 显式端口策略：只要站点启用 HTTPS 且全局 H3 端口开启，即可通过该端口接受 HTTP/3。
- QUIC demux、HTTP/3 listener 和 Alt-Svc 发布保持同一端口判断语义，修复只看站点级 H3 开关导致路由不一致的问题。
- 修复 H3 下游适配到 Pingora 时使用 HTTP/3 version 触发 H1 上游序列化 panic 的问题。
- 修复 H3 GET/空请求体结束语义，避免请求体未正确 finish 导致上游通道关闭。
- 修复 H3 响应任务处理过早返回 done 的问题，确保响应体完整发送。
- 新增 `h3_probe` 诊断工具，用于 release pod 内对指定 host/SNI/URI 做 HTTP/3 并发探测和 RPS 统计。

## 热路径性能优化

- 新增 compiled WAF、compiled cache、compiled header、compiled rewrite/auth 方向，减少请求热路径 JSON 解析、字符串小写化、正则重复构造和动态条件解释成本。
- Basic Auth fallback 去掉不必要的 JSON clone 和重复格式化，正常配置优先走 compiled auth plan。
- Rewrite replacement 改为一次扫描展开 `$0`、`$1` 等 capture，避免对每个 capture 全串 `replace()`。
- 模板渲染和 cache key 变量展开改为一次扫描，减少每次渲染的 regex/per-render allocation。
- 访问日志上传从共享 `Receiver + Mutex` 改为 dispatcher + per-worker queue，避免多个 worker 持锁 `.recv().await` 串行化。
- 访问日志管线支持按队列、批量大小和 CPU 并行度自动推导上传并发，默认不写死固定 worker 数。

## RKE2 部署

- 新增/完善 RKE2 manifest：Namespace、Secret 示例、Runtime ConfigMap、Deployment、公网 LoadBalancer、内部 Headless Service、NetworkPolicy、Lease RBAC、Longhorn RWX StorageClass 和缓存分片 PVC。
- Runtime 配置支持 `runtime.mode=rke2`，启用内部 API、Leader 选举、集群 cache metadata fanout、RKE2 cache shard 和集群统计聚合。
- Deployment 暴露 TCP/80、TCP/443、UDP/443 和内部 TCP/19090；公网 Service 使用 `externalTrafficPolicy: Local` 保留源 IP。
- 增加 `TZ=Asia/Shanghai`，统一容器日志时间展示。
- 增加 startup/readiness/liveness probe，探测内部 `/internal/v1/health`。
- 增加 pod anti-affinity，尽量把多副本分散到不同 Kubernetes 节点。
- Secret 示例补充 `accessLogPipeline`，便于在高流量环境中显式控制日志队列、批大小、并发和重试行为。

## 项目清理

- 移除不应进入仓库的 IDE、本地工具和运行时文件：`.idea`、`.qoder`、`runtime/script_configs.json`。
- 移除本地 GeoLite2 mmdb 和临时 RPC 分析 txt 文件。
- `.gitignore` 增加 `/runtime/`、`GeoLite2-*.mmdb`、本地 RPC 分析 txt 和 `app-*.js`。
- 保留 `tests/real_api_config.rs`：该测试默认跳过，只有设置 `CLOUD_NODE_REAL_API_TEST=1` 才连接真实控制面，且不包含真实密钥。

## 已验证结果

- 本地允许检查已通过：`cargo check`、`git diff --check`、`cargo check --tests`。
- release pod 已验证 WAF：防御模式 `/test1` 返回 403；观察模式匹配但不阻断；通过模式跳过 WAF；搜索引擎 UA 在区域限制中放行，普通 UA 被区域限制阻断。
- release pod 已验证 HTTP/3 可访问，并输出 HTTP/1.1、HTTP/1.1 keepalive、HTTPS、HTTP/2、HTTP/3、回源 HTTP/1.1 的 RPS 对比数据。

## 已知后续优化

- HTTP/3 回源连接当前仍缺少 QUIC/H3 session 复用，高并发回源场景仍有优化空间。
- IP list 大批量增量同步仍会逐 item recompute；如果控制面一次下发大量 CIDR，后续可按 server/kind/target 批量重算。
- RKE2 多 pod 仍共用同一控制面 nodeId；当前通过 Leader 选举避免重复上报关键指标，但长期应由控制面提供 per-pod node identity 或 pod-level 实例身份。
