# cloud-node-rust 1.1.7

## 概述

1.1.7 聚焦 L4 纯转发性能、运行时内核参数调优可观测性、UDP 热路径降耗和监控后台开销收敛。该版本将启动时的 Linux sysctl 调优独立为运行时模块，按节点日志逐项上报调优结果；TCP relay 在正常压力下回到纯 `read().await`，避免空闲连接周期唤醒；UDP 纯转发端口绕过 QUIC/H3 demux，UDP session idle 和指标上报也改为 deadline/批量模型，降低小包和空闲场景 CPU。

## L4 性能

- TCP relay 正常压力下不再包 1 秒 timeout 轮询，只有内存/FD/连接压力触发时才启用压力 idle timeout，降低空闲 TCP 连接 CPU。
- 启动时上报 L4 性能摘要，包括 zero-copy 状态、TCP copy buffer、TCP accept worker、UDP demux worker 和 UDP socket buffer。
- zero-copy 未启用时通过启动日志和节点日志提示 `cloud-node zerocopy --enable`，保持默认 async copy 行为不变。

## UDP 热路径

- UDP 端口按用途分类：普通 UDP 端口由直接 UDP listener 处理，HTTP/3 和 `@quic` 透传端口才进入 QUIC UDP demux。
- 普通 UDP 端口跳过 QUIC ClientHello 解密、CID route、H3 fallback 和 pending route 逻辑，减少纯 UDP 转发每包开销。
- UDP session idle 检查从固定 5 秒 tick 改为 `last_activity + timeout` deadline，避免大量 idle session 集体唤醒。
- UDP transfer 指标改为 session 内累计，达到 1 MiB、1 秒或 session close 时 flush，减少每 datagram 的统计调用。

## 内核运行时调优

- 新增 `kernel_tuning` 模块，Linux 节点启动时在 listener 绑定前尝试运行时应用 sysctl 参数。
- 新增 `api_config.kernelTuning.enabled`，默认 `true`；设置为 `false` 可关闭自动运行时内核调优。
- 调优覆盖 BBR/fq、backlog、socket buffer、TCP buffer、端口范围、TIME_WAIT、TFO、`fs.file-max`、`fs.nr_open`、swappiness 和 dirty ratio 等运行时参数。
- 不写 `/etc/sysctl.d`、`/etc/security/limits.d` 或 systemd drop-in；这些持久化项只作为 `not_applied_persistent_only` 节点日志上报。
- 每个参数都会上报 `tag=kernel_tuning` 节点日志，包含 `key old target final status reason`，无权限或内核不支持时不会阻止进程启动。

## 监控

- `--monitor-port` 性能监控不再每秒 `refresh_all()`；CPU/内存按秒刷新，磁盘和缓存统计降频，并把磁盘统计放到 blocking 线程执行。
- 监控采样保留原有输出字段，降低开启监控页时的后台 CPU 和阻塞风险。

## 兼容性与行为变化

- `kernelTuning.enabled` 是可选配置；旧 `api_node.yaml` 不需要修改，默认仍保持启动即尝试运行时调优。
- 非 Linux 平台会跳过内核调优并上报 unsupported，不改变原有运行行为。
- 普通 UDP 与 QUIC/H3 共享端口时仍由 demux 处理；只有纯 UDP 端口会切到直接 listener。
- UDP 指标从逐包即时写入改为短周期批量 flush，统计总量保持一致，但上报可见性最多延迟约 1 秒。
