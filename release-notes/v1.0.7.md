# cloud-node-rust 1.0.7

本文件记录 `1.0.7` 的发布说明。

## 概述

1.0.7 重点强化 HTTP/3 代理路径、对象存储源站、HTTPS 场景识别、缓存读写一致性、WAF 运行时安全路径、GoEdge/FlexCDN 风格运行目录、安装脚本和压力测试工具。HTTP/3 从旧的本地 HTTPS bridge 迁移到 Pingora custom downstream/upstream seam，客户端 H3 请求可以进入完整代理 pipeline，并在符合条件时尝试真正的 origin HTTP/3；对象存储源站补齐多云 provider、签名、bucket 获取方式和缓存流程；缓存侧修复 `writeCache` / `readCache` 竞态与 key 不一致问题，减少控制面 RPC 缓存操作误判。

本日志已合并同一问题的连续修复提交，只保留最终对功能、稳定性、性能和运维有意义的变化。

## HTTP/3 代理能力

- 移除 HTTP/3 本地 HTTPS bridge 路径，客户端 H3 请求改为通过 Pingora custom downstream session 进入完整代理 pipeline。
- H3 请求体和响应体改为流式转发，不再受旧 bridge 的 8MiB request body 和 32MiB response body 限制。
- 新增 origin HTTP/3 custom connector/session，在直接 H3 下游请求、TLS origin、origin 显式开启 HTTP/3 且非 gRPC / Upgrade 请求时尝试 upstream H3。
- 新增 origin H3 能力状态和失败退避，失败后短期回退到 H1/H2，避免持续盲探不可用 origin。
- 新增 `http3Enabled` origin 配置字段，并兼容 `supportsHTTP3`、`enableHTTP3`、`enableHttp3` 别名。
- H3 listener 改为等待 runtime reload 通知，不再依赖固定 10 秒轮询响应配置和证书变化。
- `supportMobileBrowsers=false` 现在同时影响 Alt-Svc 广告和直接 H3 入口，移动端直接访问 H3 端口会返回 421。
- SNI passthrough 场景暂不接入 H3，H3 入口遇到 passthrough 站点返回 421，避免错误代理语义。

## 上游、健康状态和多协议代理

- 为 HTTP、H3、SNI passthrough、TCP、UDP 路径补齐 origin id / origin role 元数据，便于统一健康状态记录。
- SNI passthrough、TCP、UDP 回源选择支持主备 origin，主 origin 标记 down 后可选择 backup origin。
- HTTP/3 origin 选择显式排除 gRPC、WebSocket 和其他 Upgrade 请求，避免不支持的协议被错误发送到 H3 upstream。
- 暴露 Pingora `http_proxy_custom` helper，使业务层可以使用 custom upstream connector，同时继续初始化 Pingora proxy modules。

## 对象存储源站和 HTTPS 场景

- 新增对象存储源站支持，覆盖腾讯云 COS、阿里云 OSS、华为云 OBS、百度云 BOS、七牛云 Kodo、Amazon S3、Backblaze B2 和 S3-compatible provider。
- 对象存储支持指定 bucket、URL path 前缀、URL query 参数和子域名四类 bucket 获取方式，并按 provider 处理 path-style / virtual-hosted-style 访问。
- 阿里云 OSS 支持将 URL 中的 `x-oss-*` 参数纳入签名和回源请求，用于图片处理等对象处理能力。
- S3-compatible 签名使用规范化 query 作为实际回源 query，避免签名和发送请求不一致。
- 对象存储源站访问日志显示 provider 与 bucket 名称，不再显示内部 IP:port，便于控制面识别真实源站。
- 修正 HTTP/2、HTTP/3、TLS 下游和 HTTPS URI 的 scheme 判断，避免自动 HTTP 到 HTTPS 跳转、WAF、缓存 key、访问日志和 HLS 处理误判。
- 对象存储 endpoint 仍遵守 LAN/private 地址限制，避免未授权的内网回源。

## 缓存和 RPC 稳定性

- 修复 `writeCache` / `readCache` 之间的竞态条件，避免写入尚未完成时读取失败或误判。
- 修复 RPC 缓存 key 格式不一致问题，确保控制面写入和读取使用同一 key 规则。
- 重构预取逻辑并移除旧 `WriteCacheMessage` 路径，降低重复状态和并发边界复杂度。
- 强化 cache stream 和 WAF runtime path，减少异常输入或运行时状态变化导致的失败。

## 安装和运维

- 新增 `scripts/install-rust-cloud-node.sh` 安装脚本，支持版本参数和非交互安装。
- 安装脚本在管道执行时保持交互能力，并将 secret 输入显示为星号而不是完全隐藏，降低误输入概率。
- 运行目录调整为 GoEdge/FlexCDN 风格：配置写入 `configs/api_node.yaml`，运行数据写入 `data/`，daemon 日志写入 `logs/run.log`。
- PID、状态、封禁 IP、metrics、缓存和 GeoIP 默认使用 `data/` 下路径，并保留旧 `api_node.yaml`、`../data/*` 和工作目录 GeoIP 文件的读取 fallback。
- 安装脚本 fresh/migration/dry-run 会创建 `configs/`、`data/`、`logs/`，并在迁移时将旧根目录配置和旧 `../data` 状态复制到新布局。
- `docs/operations.md` 增加 Rust cloud-node 安装和运维说明。
- README 增加安装脚本入口和 1.0.7 发布说明入口。

## WAF 人机验证

- 修复 JS Proof-of-Work 脚本语法错误，浏览器验证脚本现在能正常执行。
- WAF token 改为按 `lifeSeconds` 生成和持久化过期时间，并保留旧 token key 兼容验证。
- `captcha` 动作新增本地 slider/gesture 验证页，结合 token、PoW、拖动耗时、最终位置和轨迹样本做服务端校验。
- `js_cookie` 保持无感 JS/PoW 语义，自动完成 PoW 后写入 Cookie 并由服务端二次校验。
- `get_302` / `post_307` 保持跳转语义，通过 `Set-Cookie` 种跳转验证 token，避免服务端同步计算 PoW 放大 CPU 成本，也避免把 challenge token 追加到会转发给 upstream 的业务 URL query。
- 兼容 `js_cookie` / `jsCookie` / `jscookie` / `js-cookie` 动作别名。
- 默认验证页改为响应式卡片 UI，加入 no-store、nosniff 和 same-origin referrer 策略。

## 压力测试与诊断

- 新增全栈压力测试命令，用于评估节点极限 QPS 和端到端代理路径表现。
- 保留 H3、缓存、WAF 和安装路径的关键诊断日志，便于定位发布后运行问题。

## 已知限制

- origin HTTP/3 当前还没有连接池，每次 custom upstream H3 请求会新建 QUIC/H3 连接，高并发场景仍需继续优化。
- origin HTTP/3 的 same-request 失败回退依赖 Pingora retry 行为，仍需要真实 H3 origin 流量测试确认。
- origin HTTP/3 TLS 能力尚未完整覆盖自定义 CA 和 mTLS/client cert 与 H1/H2 的完全等价语义。
- WAF 人机验证是本地 slider/gesture + JS Proof-of-Work + token 绑定方案，用于提高脚本和视觉自动化成本；它不是外部专业 CAPTCHA 服务，也不承诺不可绕过。`useGeetest` 字段仍未接入外部 Geetest 服务端校验。
