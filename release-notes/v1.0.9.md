# cloud-node-rust 1.0.9

本文件记录 `1.0.9` 的发布说明。

## 概述

1.0.9 重点修复缓存规则误命中接口路径的问题，并针对响应热路径和 SNI passthrough 做性能优化：CPU 密集型响应转换改为基于节点压力的自适应限流，减少 outbound WAF 无 body 规则时的响应体拷贝和重复检查，SNI 转发改为索引查找并降低 ClientHello 检测和转发统计开销。

## 缓存修复

- 修复控制面下发的文件扩展名缓存条件 `fileExt` 未被匹配器正确识别的问题。
- 文件扩展名匹配统一使用请求 path 的 `${requestPathLowerExtension}`，不会再因为 query string 中包含点号而误把接口请求识别为静态文件。
- 未命中缓存规则、跳过规则、Range 直通、请求 no-cache、HLS 加密请求和缓存关闭路径都会同步清理请求级缓存状态，避免残留 `cache_ref` / `cache_key` 造成错误 cache hit。
- 强制写入 `Cache-Control` / `Expires` 前先检查方法和状态码是否允许缓存，默认仍只缓存 `200`，以及显式允许的 `206`；`201` 不会被默认缓存，也不会被错误标记为 public max-age。

## 响应热路径优化

- 新增自适应 CPU 转换门控，基于 CPU 数量和节点压力动态调整并发额度，压力升高时自动减少 WebP、HTML/CSS/JS 优化和 HLS 加密/重写的 CPU 并发。
- WebP 转换在响应头阶段只保留转换名额，真正 CPU in-flight 只在最终转换时占用，避免慢源站或慢客户端长期占用 CPU 转换额度。
- HTML/CSS/JS 优化在 CPU 门控拒绝或转换失败时返回原始响应体，优先保护尾延迟。
- HLS playlist rewrite 和 TS segment AES 加密走必需转换门控；加密段不会在过载或缺少 key 时降级为明文返回。
- outbound WAF 只有在启用的出站规则引用 `responseBody` 时才缓存响应体并按 chunk 重新评估，普通 header/status 出站规则不再承担响应体拷贝成本。

## SNI passthrough 和四层转发性能

- SNI passthrough 服务路由新增 exact/wildcard 索引，连接进入时按端口和 SNI 直接查找，避免扫描全部服务。
- wildcard 语义保持兼容：`*.example.com` 继续匹配 `example.com` 和子域名。
- ClientHello SNI 检测降低初始 peek buffer 和等待时间，常规单 TLS record 解析避免拷贝；分片 ClientHello 仍会临时拼接握手数据以保持兼容。
- TCP/SNI 转发统计从每 chunk 写入改为 1MiB 阈值批量 flush，并在连接结束或异常断开时 flush 剩余字节，降低大流量透传路径统计开销，同时保留长连接期间的实时统计更新。
- SNI passthrough 访问日志改为使用连接进入时记录的真实开始时间，不再按上传时刻减 duration 反推，避免长连接或延迟上报导致时间偏移。

## 节点状态上报

- 节点成功同步配置并上报在线时，会同步调用 `updateNodeIsInstalled` 标记已安装，避免控制面继续停留在安装/同步中状态。

## 超时配置接入

- 集群级 `httpAll` 里的源站性能超时字段现在会完整进入运行时配置，不再被默认值覆盖。
- 源站连接、读取、空闲和写入超时都支持从集群级配置回退；单源站显式非零配置仍优先。
- 客户端自动读/写超时现在也会从集群级 `httpAll` 生效。
- 源站连接/读取/写入超时在访问日志与响应层会按 `504 Gateway Timeout` 处理。
