# cloud-node-rust 1.1.0

本文件记录 `1.1.0` 的发布说明。

## 概述

1.1.0 新增 `@quic`/HY2 非 obfs UDP 域名透传能力，并把 HTTP/3 与 UDP 透传统一到共享 UDP demux：节点可以在同一 UDP 端口上同时承载 H3 站点和按 QUIC Initial TLS SNI 分流的 HY2/Hysteria2 服务。本版本同时修复节点任务同步闭环，避免控制面任务未确认时本地推进版本导致节点状态停留在同步中。

## `@quic` / HY2 UDP 透传

- 新增 QUIC Initial 探测器，解析 long header、Initial key、header protection、AES-GCM payload、CRYPTO frame、TLS ClientHello、SNI 和 ALPN。
- 支持同一 UDP datagram 内 coalesced Initial packets，并合并 CRYPTO fragment 后再解析完整 ClientHello。
- `@quic` 服务域名会在运行时移除标记并按 `SNI + UDP 监听端口` 建立 exact/wildcard 索引。
- 非 obfs HY2/Hysteria2 可直接通过 QUIC TLS SNI 按域名转发；obfs 流量不做域名识别。
- `@quic` 不进入 HTTP/3 L7 desired ports，也不生成访问日志。

## 共享 UDP demux 和端口优先级

- HTTP/3 与 UDP/HY2 透传可共享同一个 UDP 监听端口，避免 H3 和 UDP passthrough 同端口 bind 冲突。
- H3 ALPN 且命中 L7 站点时进入 HTTP/3，非 H3/HY2 且命中 `@quic` 时进入 UDP 透传。
- 未能按 SNI 命中 `@quic` 的包先匹配普通 UDP 服务；只有该端口唯一配置了一个 `@quic` 服务时才作为 fallback，避免 `@quic` 抢占普通 UDP。
- demux route 按客户端地址维护生命周期，增加 pending route、每 IP 新 route 速率、总 route 数和 reassembly bytes 上限，限制异常 QUIC Initial 带来的内存压力。
- existing passthrough route 使用 `Bytes` 直接投递到 UDP session，减少一次热路径拷贝。
- demux listener 会周期性 reconcile，并拉长 bind retry 窗口，降低运行时 reload 后旧 socket 短暂占用导致端口未恢复监听的风险。

## 端口范围和路由索引

- HTTP/3 desired ports、UDP 服务匹配、SNI passthrough 索引和 `@quic` 索引都完整支持 `443-445` 这类端口范围。
- `@quic` 不使用端口 `0` 兜底；唯一 by-port fallback 只在同一端口仅有一个 `@quic` 服务时生效。
- TCP SNI passthrough 路由检查改为单次配置读锁完成，保留精确 L7、精确 passthrough、通配 L7、通配 passthrough 的优先级。

## 访问日志和时间字段

- 移除 `@quic` 访问日志聚合和上报，普通 L4 与 `@quic` 都不产生访问日志。
- TCP SNI passthrough 继续沿用对应 L7 服务访问日志配置，并遵守全局访问日志开关。
- L4/SNI passthrough 访问日志时间字段统一按 UTC 输出，避免本地时区造成日志时间偏移。

## 节点任务同步

- 配置同步失败时仍会拉取 NodeTask，但全局配置类任务会延后确认，不会错误上报完成。
- 只有任务处理成功且 `ReportNodeTaskDone` 成功后才推进本地 `task_version`。
- 上报任务完成失败时立即停止处理后续任务，避免本地跳过仍未被控制面确认的任务。
- 节点生命周期任务会调用 `updateNodeIsInstalled`，确保安装/升级任务闭环。
