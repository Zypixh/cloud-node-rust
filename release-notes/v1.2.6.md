# cloud-node-rust 1.2.6

本版本围绕两条主线：**内存治理闭环**与**连接生命周期可靠性**。相对 1.2.5，共修复 10 项审计确认的问题（8 项 P1、2 项 P2），覆盖配置同步、内存回收、增量同步指纹、L4 连接取消、指标持久化与存储背压；同时 GeoIP 切换为 mmap，connectionShadow 指标首次接入生产路径。

无统计 key、值编码、缓存或 Mace 数据格式变化，旧数据库直接兼容，可从 1.2.5 直接升级。

## 变更总览

| # | 领域 | 1.2.5 的问题 | 1.2.6 的修复 |
| --- | --- | --- | --- |
| 1 | 配置同步 | 高压时先清空路由再构建新代，物化期间新请求全部 miss | 先构建新代再原子发布，空路由窗口消除 |
| 2 | 配置准入 | 准入 32 次失败后仍强制全量构建，低内存下可能 OOM | 准入失败保留旧代、不推进游标、下轮重试 |
| 3 | 内存回收 | 请求热路径同步执行全局缓存清扫 | 热路径只做原子通知，回收移到专用线程 |
| 4 | 回收调度 | 触发被冷却期消耗后同级压力永不重试；回收统计虚报 | 触发失败回滚状态机重试；统计回归真实计数 |
| 5 | 同步指纹 | 删除/停用后指纹不清理，同 JSON 被跳过；指纹未含全局上下文 | 删除即清理、全量快照修剪、指纹混入全局盐值+版本 |
| 6 | L4 取消 | 所有取消都记为 L4Drain；channel 关闭误断连；协议切换存在 guard 竞态 | 类型化原因贯穿、关闭不再误判、切换时重放取消 |
| 7 | 存储背压 | Mace 前台写入无背压，慢盘/checkpoint 堵塞时无限积压 | 启用桶级写背压，写入方全部在阻塞线程/有界队列 |
| 8 | 指标持久化 | 写失败前已推进 delta 基线，数据永久丢失；Top IP 上传失败不恢复 | 基线写成功后才提交；Top IP 失败回灌重试 |
| 9 | GeoIP | City/ASN 数据库整体读入匿名内存 | 切换 mmap，RSS 降低、页缓存可回收 |
| 10 | 连接统计 | connectionShadow 恒为 0，connectionCount 非物理连接口径 | 五类 shadow 传输计数接入生产接受/转发路径 |

## 1. 配置同步：先构建、后发布

```
1.2.5（高压路径）:
  收到全量快照 → 注销健康检查 + 清空路由/编译计划 → 物化新配置 → 原子发布
                    └───── 空路由窗口：物化期间所有新请求查不到路由 ─────┘

1.2.6:
  收到全量快照 → 内存准入（最多重试 32 次）
                    ├─ 通过 → 物化新配置（旧代全程继续服务）→ 原子发布 → 推进游标
                    └─ 失败 → 保留旧代 + 请求一次 Critical 回收 → 游标不动，下轮重试
```

高压下健康检查改为延迟注册（不再逐站点立即探测），避免全量快照一次性把数百个探测任务压进内存。

## 2. 准入失败不再强制构建

`materialize_runtime_servers` 在准入重试耗尽后直接返回空结果（`admitted=false`）。所有发布方——全量同步、单服务器同步、用户站点同步、`apply_server_snapshot`——统一处理：不发布、不写指纹、不推进配置游标；控制面在下轮同步重新下发。低内存时节点宁可停留在上一个有效配置，也不再冒着 OOM 风险强行重建。

## 3. 内存回收异步化

```
1.2.5: 请求线程 memory_snapshot() → 观察到压力 → 【当前线程同步】清 L1/Bloom/Geo/UA/TLS/WAF
       → 延迟抖动、锁竞争、缓存反复重建

1.2.6: 请求线程 memory_snapshot() → 原子合并 pending 压力级 + unpark（纳秒级，无锁）
       memory-reclaim 线程: park(≤5s) → 取出 pending 级别 → 协调器采样 → 触发回收（后台执行）
```

重复通知按“最高压力级”合并，唤醒风暴收敛为一次 park 唤醒；每 5 秒的兜底采样保留，持续压力仍按退避节奏重试。此前为防递归而设的线程局部守卫一并移除——观察压力的路径不再可能触发同步回收。

## 4. 回收触发不再丢失

```
observe(level) → 升级采样达标? ─否→ Hold（继续采样）
        │是
        ▼
  Trigger(level) → request_reclaim()
                      ├─ 成功 → 记录冷却/退避
                      └─ 失败（冷却中/已有回收在跑）→ 回滚状态机 → 5s 后重新采样重试
                                                  （1.2.5 在此永久卡死）
```

附带修复：Geo/UA 回收不再虚报“删除 1 条”，而是返回真实逐出的条目数，零进展退避算法据此正确拉长重试间隔。

## 5. 增量同步指纹生命周期

```
指纹值 = hash(全局运行上下文盐值 ‖ 包版本 ‖ 站点 JSON 的 MD5)

写入: 增量同步发布成功后 mark
清除: remove_server / remove_user_servers（站点或用户被删除、停用即失效）
修剪: 每次全量快照后清理已不存在的 server:/user: 条目（DashMap 不再无限增长）
失效: 全局 HTTP 配置、节点层级、父节点、tiered bypass、LAN 开关任一变化；或二进制升级
```

1.2.5 的缺陷：删除/停用站点后指纹残留，重新启用相同 JSON 会被“已发布”跳过，而实际路由并不存在。盐值机制同时保证：全局设置变更或升级二进制后，所有增量映射强制按新上下文重建一次。

## 6. L4 连接取消：类型化原因贯穿全程

```
取消原因 → relay 结束口径的映射:
  DefenseBlocked                                 → L4Drain（L4 防御排水，维持原语义）
  ManagementShutdown / ServiceExit / ExplicitIdleReclaim → Cancelled(原因)
  channel 关闭（sender 被 drop）                  → 不再中断，等待 IO 自然结束
                                                   （1.2.5: 一律记为 L4Drain 且误断连）

协议切换（SNI 接管 / HTTP1→H2 升级）:
  1.2.5: drop(Http1 guard) → register(新 guard)    ← 间隙内到达的防御取消会丢失
  1.2.6: switch_protocol: 注销旧条目 → 读取旧 channel 的 pending 取消
                          → 注册新条目 → 将 pending 取消重放到新 channel
```

## 7. Mace 写入背压

桶级 `enable_backpressure` 由 false 改为 true。所有 Mace 写入方本来就是专用阻塞写线程、`spawn_blocking` 任务或有界队列（容量 8192）的消费者，因此慢盘或 checkpoint 堵塞时生产者被限速等待，而不是把脏页无限堆积进内存。Tokio reactor 仍不执行同步写，前台请求路径不受影响。

## 8. 指标持久化失败可重试

```
1.2.5: 计算 delta → 立即推进基线 → 写 Mace ─失败→ 本窗口数据永久丢失
1.2.6: 计算 delta → 写 Mace ─成功→ 推进基线
                      └─失败→ 保留旧基线，下一轮重发同一批 delta
```

Top IP 上报同理：连接失败或上传失败时，把 flush 出的行回灌 tracker，与下一窗口合并重传，不再静默丢失。

## 9. GeoIP 切换 mmap

City/ASN 读取器从 `Reader<Vec<u8>>`（数据库整体进入匿名内存）切换为 `Reader::open_mmap`。数据库页改由页缓存承载，内存压力下可被内核回收，进程 RSS 显著下降。安全性依赖“临时文件 + 原子 rename”的安装方式（内置更新流程即如此），不存在原地改写导致的并发读风险。

## 10. connectionShadow 接入生产

RAII 传输计数点（连接/会话建立时 +1，销毁时自动 -1）：

- **DownstreamTcp**：HTTP/1、H2、SNI、AF_XDP、TCP/TLS 代理的全部下游接受点
- **UpstreamTcp**：TCP 代理的三个后端连接点
- **UdpSession**：UDP 透传会话任务
- **QuicConnection**：HTTP/3 连接
- **RpcTransport**：node stream 连接生命周期

状态上报中的 `connectionShadow` 不再恒为 0，可用于核对 `connectionCount` 与真实物理连接数的偏差。

## 同分支一并交付的其他改进

- 连接注册表取消消息从布尔量演进为类型化枚举（防御封禁 / 管理关闭 / 服务退出 / 显式空闲回收）。
- 站点活动计数 RAII 化：失败、取消、配置热更新后活动连接与请求计数归位。
- Mace WAL/缓存/桶参数按机器内存分档（512MiB/1GiB/2GiB 三档），大额常驻分配受控，旧库兼容打开。
- 内存可用量观测修正：raw available 不再叠加双重 reserve；极低可用量直接限制新分配。
- HTTP 请求统计聚合器支持 flush 后 restore，上传失败不丢样本。
- partial cache 写入器只在按预期代际打开时才对 purge 代际做栅栏，避免无关清理放弃合法写入。
- 新增 SNI 断流审计与修复方案文档（`tasks/`），以及 SNI 场景测试用 Dockerfile。

## 行为变化与兼容性

- 无统计 key、值编码、缓存策略或 Mace 数据格式变化。
- relay 关闭诊断日志新增 `relay cancelled (<reason>)` 形态；如有外部系统解析关闭日志请注意。
- 高压下配置同步可能推迟发布（期间继续使用旧版本服务），属于预期行为。
- Mace 慢盘时前台统计写入出现有限等待，属于预期背压。
- GeoIP 数据库必须以原子替换方式更新（内置更新已如此）；请勿原地改写 .mmdb 文件。

## 升级说明

- 可从 1.2.5 直接升级，无配置迁移、无数据迁移。
- 升级后首次增量同步会因指纹盐值变化对各站点重建一次映射，属一次性开销。
- 建议升级后观察 `connectionShadow` 与 `connectionCount` 的差值，验证连接口径修复效果。
