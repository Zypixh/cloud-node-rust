# cloud-node-rust 1.1.3

## 概述

1.1.3 覆盖 `v1.1.2` tag 之后的已提交优化和当前工作区修复。已提交部分包括多 Cookie 读取、SNI/TCP 零拷贝转发、模板安全、client-agent IP 本地库、热路径配置预编译、runtime 热加载、nodeStream 稳定性和安装器升级保留运行目录；当前修复继续补齐 UAM 五秒盾、HTTP 缓存切片、WAF、代理协议、集群同步、访问日志和控制面配置兼容性。

## 1.1.2 后已提交变更

### Cookie 与请求匹配

- 完整读取多个 `Cookie` 头，兼容 HTTP/2 将 Cookie 拆成多行的场景。
- WAF matcher、WAF challenge 校验、缓存编译变量和请求参数提取统一使用合并后的 Cookie 视图，避免只读取第一行 Cookie 导致误判。
- Cookie 参数规范化和按名称取值逻辑统一，减少不同路径对 Cookie 的解析差异。

### SNI 与 TCP 转发

- SNI 探测支持分片 ClientHello，探测过程不消费已读取字节，避免 TCP/SNI passthrough 后续转发缺首包。
- SNI 探测总超时和空闲超时上调，降低真实客户端慢速握手被误判的概率。
- Linux TCP/SNI passthrough 接入 `splice` 零拷贝双向转发；非 Linux 或不满足条件时保留普通双向 relay fallback。
- TCP 转发保留半关闭语义，并在双向 relay 完成后刷新连接、流量和回源健康指标。
- TCP manager 在握手前检查本地封禁状态，被封禁 IP 不再进入后续 TLS/SNI 流程。
- TLS 空连接、握手失败和异常探测复用全局 special defense 统计，用于后续防护策略判断。

### 模板安全和请求热路径

- 页面模板默认 HTML escape，降低配置模板把请求内容反射到 WAF/UAM 页面时产生 XSS 的风险。
- 只有重定向地址等确实需要原样渲染的位置继续使用 raw template，避免把 URL 模板错误转义。
- client-agent PTR 反查增加并发限制和超时控制，避免大量请求把阻塞解析压到请求热路径。
- HTTP dimension 队列满时不再在请求线程同步 fallback 聚合，改为丢弃并记录计数，避免高压下拖慢 worker。
- plan 最大上传限制和流量超限提示预先派生缓存，减少每个请求重复解析 plan JSON。

### Client Agent IP 本地库

- 新增控制面 client-agent IP 增量同步，本地保存 IP、client-agent 信息和同步游标。
- RocksDB 存储模式下持久化 client-agent IP 索引；非持久化模式使用内存索引。
- WAF 可基于本地库判断已验证搜索引擎 IP，减少每次请求在线查询或 PTR 反查成本。
- client-agent IP 同步采用后台队列和 worker 处理，避免控制面数据同步阻塞主请求路径。
- gRPC API 文档补充 ClientAgentIP 服务和增量同步接口。

### 性能和配置预编译

- Plan 派生配置在配置刷新时预计算，请求热路径直接读取最大上传大小和流量限制响应体。
- Header domain matcher 预编译 exact、suffix、wildcard、regex 规则，并规范化 Host 后匹配，减少每次请求重复编译和分配。
- Compiled WAF 对 SQLi/XSS/命令注入等常见 operator 使用直接 helper，降低通用表达式评估开销。
- 配置刷新时同步更新 plan 派生缓存，避免 plan 或 user plan 变化后继续使用旧限制。

### Runtime、HTTP/3 和生产噪声

- Pingora proxy 接入 downstream parse error hook，对畸形 HTTP、TLS-on-HTTP、H2C 探测等场景做分类处理。
- 明确的错误探测降为 debug 或专门防护统计，减少生产环境无效请求刷屏。
- HTTP/3 证书选择改为动态 resolver，证书更新时不再重启 listener，降低热加载中断风险。
- cache disable 避免对未启用缓存的实例重复执行无意义关闭。
- 内核参数调优改为更保守的可选行为，`fq`/`bbr` 等环境相关项降级为 debug 记录。
- RPC keepalive 和连接超时调整，降低网络抖动下控制流误断概率。

### RPC 控制流

- nodeStream 针对 `http://` plaintext API endpoint 恢复低层 HTTP/2 gRPC stream 路径，避免服务端等待首包 stream message 时客户端先因响应头超时断开；TLS/非 plaintext endpoint 继续使用标准 tonic 路径。
- 心跳间隔调整为 30 秒，并在 outbound 队列已满或关闭时安全处理 `try_send`。
- 探测路径与运行路径保持一致：plaintext endpoint 使用低层 h2，其他 endpoint 使用 tonic client。

### 安装和升级

- 安装器升级时优先识别已有 service `WorkingDirectory`、`/usr/bin/cloud-node` wrapper 的 `cd` 目录、现有二进制目录和常见运行目录。
- 升级流程会保留并迁移 `configs/api_node.yaml`、旧版 `api_node.yaml`、`state.json`、`blocked_ips.json`、`metrics.db` 等运行数据。
- 避免升级把既有运行目录重置到默认目录，降低节点重新注册、状态丢失或指标丢失风险。
- 已注册 systemd unit 时，`cloud-node start/restart` 优先委托给 `systemctl`；一键升级脚本也直接使用 `systemctl restart/start`，避免升级后误走内置 daemon 分支。
- 运行日志现在由节点自身追加写入 `logs/run.log`，systemd 前台托管和内置后台模式都能在运行目录保留本地日志；新注册的 service 会显式设置 `CLOUD_NODE_HOME`。

## UAM 五秒盾

- UAM 挑战页从错误响应改为 `200 OK` 返回，验证成功使用 `303 See Other` 回跳，验证失败才返回 `403 Forbidden`，避免浏览器、下载器或中间代理把正常挑战流程当作访问失败。
- `keyLife` 已接入为验证通过后的有效期；有效期内 `UAM-Pass` cookie 校验通过后不再重复挑战，`keyLife=0` 使用系统默认值。
- `minQPSPerIP` 已接入为 60 秒窗口触发条件；配置为 `0` 时任何匹配请求都会触发，配置为正数时只有单 IP 在 1 分钟内达到阈值后才触发。
- 移除 UAM 临时 IP 白名单语义，不再依赖单节点内存白名单；重复放行统一由有效期 cookie 控制。
- UAM cookie 使用本地 `api_config.secret` 做 HMAC-SHA256 签名，并绑定 IP、User-Agent hash、规范化 Host、Server ID、配置 hash、过期时间和随机 nonce；开源代码本身不泄露节点密钥，不能直接构造有效 cookie。
- UAM token 和 pass cookie 增加版本号，配置变化、站点变化或 Host/Server 变化后旧 cookie 自动失效。
- UAM 支持 `mode`：JS Cookie、PoW、Captcha/Slider；JS Cookie 模式不再强制执行 PoW。
- 验证成功后会清理临时 `UAM-Token`，减少失败 token 残留导致的重复验证。
- UAM 站点配置支持 `isPrior`，server 级 UAM 可按优先级覆盖 web 级 UAM；没有站点 UAM 时再使用全局 UAM policy。
- UAM 支持 `conds` 请求条件，只有 URL 和条件同时命中时才触发。

## URL 匹配和配置模型

- `onlyURLPatterns`、`exceptURLPatterns` 扩展为统一 URLPattern 模型，支持通配符、正则表达式、常见图片、常见音频和常见视频，并可混合使用。
- 通配符支持 `/hello/world/*`、`*/hello/world`、`*/article/*`、`*example.com/*`、`*.js` 等形式。
- 正则表达式支持 `^/hello/world`、`/hello/world$`、`/article/`、`/article/(\\d+)`、`^(http|https)://example.com/` 等形式。
- 路径类规则会同时匹配 path 和完整 URL 中解析出的 path；完整 URL 正则会匹配完整 URL；匹配前会忽略 query 和 fragment 对后缀规则的影响。
- URLPattern 字段增加 `type/patternType/matchType`、`pattern/value/url` 等兼容别名。
- UAM、缓存规则、HLS 加密、User-Agent、Referer、区域限制、基础优化等模块统一使用新的 URLPattern 语义，不再只按简单 path 截断判断。
- `HTTPRemoteAddrConfig` 新增 `requestHeaderName` 和 `isPrior`，并支持 `${header.A,B}` 多请求头展开。
- 远程地址模板支持 modifier 管线，以及 `host.first`、`host.last`、`node.id`、`node.name`、`geo.country/province/city/isp` 等变量。
- Web 配置新增 `preferWWW` 和 `trailingSlash`，用于规范化 www 和尾斜杠跳转。
- Server 配置新增 `enableProxyProtocol` 和 `locations`；Location 支持 exact/regex/prefix 匹配、priority 和 location 级 `reverseProxy`。
- HTTP 缓存 policy/ref 新增并接入 `allowChunkedEncoding`、`allowPartialContent`、`forcePartialContent`、`alwaysForwardRangeRequest`、`enableRequestCachePragma`、`enableIfNoneMatch`、`enableIfModifiedSince`、`enableReadingOriginAsync`。
- WAF policy 新增候选规则字段 `candidateRules`、`candidateTrafficPct`、`candidateVersion`，为灰度规则集统计做准备。
- WAF rule 新增 `paramFilters`，支持在匹配前对参数值执行解码、大小写、hash、trim 等过滤。

## HTTP 缓存和 206 切片

- 状态码列表语义修正：空状态码列表表示允许所有可缓存状态；`206 Partial Content` 只有在 `allowPartialContent=true` 或状态码列表显式包含 `206` 时才允许缓存。
- `skipCacheControlValues` 改为按逗号分隔后的 Cache-Control 指令做大小写不敏感精确匹配，不再用全文 contains 误伤。
- `skipSetCookie` 语义修正：只有配置开启时，响应带 `Set-Cookie` 才跳过缓存；不再为了让缓存写入强行剥离 Set-Cookie。
- `enableRequestCachePragma` 已接入：请求带 `Pragma: no-cache` 或 `Cache-Control: no-cache` 时跳过缓存直接回源。
- `enableIfNoneMatch`、`enableIfModifiedSince` 已接入：未开启时会移除条件请求头，开启后允许条件请求回源。
- `allowChunkedEncoding` 同时支持 policy 级和 cacheRef 级配置；允许 chunked 时可在无 Content-Length 的情况下跳过大小检查。
- 未启用切片时仍按完整对象缓存和响应；完整对象已命中时，客户端 Range 请求优先由完整对象缓存处理。
- 新增 `src/cache/partial.rs`，实现 206 分片缓存 key、Range/Content-Range 解析、稀疏文件写入、range 元数据、命中读取和清理。
- 分片缓存只接受单段 Range；多段 Range、非法 Range 会跳过缓存直接回源。
- 分片缓存要求源站返回 `206`、有效 `Content-Range`、可确认 total；未知总大小、带 `Vary`、总大小小于 256 KiB 的响应不会切片缓存。
- `forcePartialContent` 只在已有可用分片缓存时优先返回 206；不会为了小对象或未覆盖 range 强制制造分片响应。
- `alwaysForwardRangeRequest` 已接入：带 Range 的请求直接回源，不从缓存读取。
- 分片写入使用临时元数据文件再 rename，避免元数据半写；写入按 shard lock 合并 range。
- 分片缓存参与精确 key、prefix 和 surrogate tag 清理，避免只清理完整对象。
- Hybrid cache 对分片 key 直接走 L2，不进入 Fast L1，避免内存层误缓存不完整对象。
- cache metadata 新增 `stale_while_revalidate_secs` 和 `created_at`，并在磁盘索引、内存索引、集群 metadata fanout 中保留。
- `Cache-Control: stale-while-revalidate=N` 现在会解析并保存，为 SWR 命中和集群同步提供一致元数据。
- surrogate-key 建立反向索引，支持按 tag 清理普通缓存对象和分片缓存对象。
- cache access log 在删除 cache meta 时同步清理，减少长期运行的内存增长。
- `enableReadingOriginAsync` 字段可接收和解析，但当前不按单条 cacheRef 独立控制；实际行为取决于 Pingora cache storage 是否支持 streaming partial write，已在配置文档中说明。

## WAF 正确性和能力

- WAF legacy 和 compiled 路径都增加 GO_GROUP/GO_SET 跳转上限，防止错误配置形成循环后单请求占满 worker。
- GO_SET 行为修正为跳到指定 set，而不是只跳到目标 group 后从头重新匹配。
- preset matcher 从指定 set 继续执行时不会重复触发，避免 flow-control 跳转后重复命中 preset。
- observe 模式会跳过更多有副作用动作，包括记录白名单、灰名单等，避免观察模式改写运行时状态。
- 请求体和响应体原始 bytes 匹配接入 legacy/compiled 路径，避免二进制内容经过 lossy UTF-8 转换后漏检。
- bytes 正则缓存区分大小写标志；WAF regex 缓存从无界 DashMap 改为 moka W-TinyLFU 有界缓存，降低大量唯一 regex 下的内存风险。
- WAF `paramFilters` 已接入 legacy/compiled 路径，可对参数先执行 filter 再匹配。
- WAF 候选规则集支持按 client IP + path 稳定抽样，并记录候选规则命中、阻断、观察统计。
- forwarded-for 类请求头只在直接对端是本机、私网或链路本地地址时信任，避免公网客户端伪造真实 IP 影响 WAF、CC、名单和日志。
- IPv4-mapped IPv6 会规范化为 IPv4 后参与名单、远程地址和本地地址判断。
- IPv6 ULA/link-local 判断修复，避免运算优先级导致本地地址识别错误。
- IP 黑白灰名单新增 IP range 支持，`ipFrom/ipTo` 不相等时会按闭区间匹配。
- WAF 状态增加 GC 任务，定期清理过期黑白灰名单、过期 range、过期 counters、空闲 rate limiter 和带宽计数器。
- server/IP rate limiter 记录原始 quota，配置热更新后会替换旧 limiter，避免旧 QPS 限制长期生效。
- CC 带宽限制增加单 IP 1 秒窗口 byte counter。
- 出站 WAF 命中后会生成独立阻断响应，移除源站 length、transfer-encoding、content-encoding、etag、last-modified、cache-control 等头，不再泄露源站响应体。
- 出站 WAF 响应体检查后会继续发送已缓冲内容，避免检测窗口之外的正常响应被截断。
- WAF 阻断响应不会进入缓存。

## UAM/WAF 页面和 HTTP 状态码

- UAM 页面使用 cloud-node 路由 `/.well-known/cloud-node/waf-verify`，挑战响应不再复用 403 错误流程。
- WAF challenge、Captcha/Slider 和 UAM 共享验证路由，但 UAM 使用独立 `__waf_uam=1` 标识和独立签名 token。
- WAF/UAM 模板变量渲染继续保留 requestId、status/statusMessage 等上下文。

## 代理、路由和协议

- HTTP/HTTPS listener 身份增加 TLS 与 PROXY Protocol 开关；同端口配置冲突会记录日志并保留已有配置，不再静默覆盖。
- HTTP 和 TCP listener 支持 PROXY Protocol v1/v2 入站头解析；无 PROXY 头保持兼容，非法或不完整 PROXY 头会丢弃连接。
- PROXY Protocol v2 只接受 stream transport；LOCAL/UNSPEC 会消费头但保留原始 socket 地址。
- 新增统一 `src/proxy_protocol.rs` 解析器，HTTP 和 TCP 复用同一解析逻辑。
- Location 路由新增编译缓存，支持 exact、regex、prefix 匹配，并在配置更新、单站更新、删除站点时清理缓存。
- location 级 `reverseProxy` 可以覆盖站点默认回源配置。
- WebSocket 回源会转发 `Sec-WebSocket-Protocol`，支持 graphql-ws、mqtt 等子协议协商。
- HLS playlist 处理改为等响应体完整后再重写，避免源站 chunked 返回时按 chunk 输出截断 playlist。
- 源站重定向 `Location` 中如果暴露内部 origin host，会按客户端 Host 改写。
- www 和 trailing slash 规范化跳转接入请求路径。
- L1 到父节点的内部头仍会在回源前剥离，避免泄露到源站。

## 集群和 RKE2 多副本

- cluster leader 状态从两个 atomic 合并为一个 packed atomic，保证 role 和 epoch 读取一致，避免 fanout 携带旧 epoch。
- leader step-down 使用原子清位，避免读取 epoch 后再写入的 TOCTOU 竞争。
- follower 上报 stats 时优先尝试上一次成功的 leader peer，并在首个成功 peer 后停止 fanout，减少多副本间无效请求。
- cluster stats 的本地 sysinfo snapshot 放到 blocking 线程执行，避免周期性卡住 Tokio worker。
- internal API 增加连接总超时，防止慢速连接长期占用任务。
- internal `/internal/v1/health` 允许无 token 访问，兼容 kubelet probe；purge/stats/metadata 等仍要求 token。
- RKE2 cache purge 支持 key、prefix、tag/surrogate-key 类型，并通过内部 API fanout 到其他副本。
- cache metadata fanout 保留 SWR 字段，远端节点不会丢失 stale-while-revalidate 语义。
- cache task 状态上报使用任务自身 `nodeClusterId`，不再固定上报 `0`。

## RPC 和控制面接入

- 控制面 proto 中 UAM policy、gRPC policy 是集合字段；UAM、缓存规则细节来自 JSON bytes，Rust 侧按 JSON 字段和兼容别名接入。
- gRPC policy 选择顺序调整为当前 `nodeClusterId`、默认 `0`、首个策略、primary 策略，避免多 API/多集群配置下选错。
- `kernelFirewallMode` 从 node JSON 接入，并在配置同步时构建 nftables/iptables/noop filter。
- IP list item 增量同步遇到无效 item 时不会推进到错误状态；会统计失败项并返回失败结果。
- IP 上报不再尝试调用需要 admin/user 凭据的创建名单接口；server scoped 上报必须带明确 list id，全局上报使用固定全局名单 ID。
- IP 上报队列满时记录按 2 的幂次节流的 warn，并暴露 dropped report 计数。
- 节点 lifecycle task（upgrade/install/start）不再尝试调用需要更高权限的 `updateNodeIsInstalled`，改为本地确认，避免任务重试循环。
- 单站/多站配置同步的 JSON hash 记录改用不 poison 的 `parking_lot::RwLock`，避免 panic 后配置同步路径永久失效。
- cache task RPC metadata 插入去掉 unwrap，避免异常 nodeId/token 触发 panic。
- 新增 HTTP firewall event 上报结构，改用 firewall service 的 notify 接口。

## 日志、统计和可观测性

- 全局访问日志配置新增 `firewallOnly` 和 `enableClientClosed`：可只记录 WAF 请求，或跳过客户端关闭产生的 499。
- log uploader 和 node log uploader 修复 sender 全部关闭后的 select 忙循环；关闭时会先 flush 剩余 buffer 再退出。
- request header 模板新增 `requestRefererBlock`，会从 Referer 提取规范化域名块。
- metrics aggregation key 新增 provider_id，上传 region provider 时只提交非 0 provider。
- GeoIP ASN reader 和 ASN cache 接入，`lookup_region_provider_id` 当前以 ASN number 作为 provider id。
- Top IP 请求数从 u64 转 u32 时改为饱和到 `u32::MAX`，避免超过 4.3B 后静默回绕。
- origin health 事件会记录健康状态、延迟和最后检查时间，并由 leader 周期性上报 node values。
- passthrough 回源连接成功/失败会推送 origin health 事件。

## 本地封禁和持久化

- Linux 本地封禁新增 kernel filter 抽象，支持 nftables、iptables 和 noop。
- nftables 表名使用 `cloud_node`，iptables comment 使用 `cloud_waf_block`。
- WAF 本地 block/unblock 和 GC 会调用 kernel filter，支持内核层快速丢弃被封禁 IP。
- 运行状态和 blocked IP 持久化改为临时文件 + fsync + rename，降低进程崩溃导致状态文件清空或损坏的风险。

## CORS、请求处理和响应处理

- CORS `Access-Control-Allow-Origin: *` 时不再同时写 `Access-Control-Allow-Credentials: true`，符合 Fetch 规范。
- 条件请求支持从缓存响应生成 weak ETag，并对 `If-None-Match` / `If-Modified-Since` 命中返回 `304 Not Modified`。
- 响应 rewrite、header 模板和 referer 相关模板都补充 `requestRefererBlock`。
- 非 UAM/WAF 阻断响应的 cacheability 判断更加保守，阻断响应不会污染缓存。
