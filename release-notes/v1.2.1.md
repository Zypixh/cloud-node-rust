# cloud-node-rust 1.2.1

## 概述

1.2.1 将节点本地嵌入式 KV 存储从 RocksDB 迁移到 [Mace](https://github.com/abbycin/mace)（`mace-kv` 0.1.1），升级 Rust 工具链与主要依赖，并修复 SNI/AnyTLS 长连接稳定性、TLS 栈与 Mace unique-IP 持久化问题。

## 存储（RocksDB → Mace）

- 本地 metrics / 防火墙封禁 / 缓存元数据索引统一使用 Mace，数据目录由 `data/metrics.db` 改为 **`data/metrics.mace`**。
- 移除 `rust-rocksdb` 及 C++ 构建依赖，Release CI 构建链更简单。
- 计数写入优化：packed server period 记录（单 key 72 字节）、热 key 内存缓存、`sync_on_write = false`（对齐原 RocksDB 异步 WAL 语义）。
- 新增 `tests/mace_storage.rs` 与 `benches/storage_bench.rs`（Mace-only）。
- 移除 legacy `blocked_ips.json` 读写与一次性迁移；运行时封禁只从 Mace `FWBLK_V1_*` 恢复。
- **修复 unique-IP 日统计丢失**：Mace 将空 value 视为 tombstone，`record_unique_ip` 改为写入非空哨兵，确保 `UIP_*` 键可被扫描恢复。

## SNI / AnyTLS passthrough

- 修复 SNI passthrough relay 半死隧道：关闭 `defer_backend_to_client_clean_shutdown`，backend EOF 立即传播到客户端。
- 为 relay TCP socket 配置 keepalive（`relay.tcpKeepaliveIdleSecs/IntervalSecs/Probes`）。
- L4 churn 事件不再 drain 进行中的 `SniTcp` 连接；passthrough TLS 端口放宽 per-IP 限制与 ClientHello peek 超时。
- passthrough backend 连接增加重试。
- 普通 HTTPS 入口的 `TcpStream` SNI passthrough 启用 zero-copy splice 路径（`relay.zeroCopy=true` 时）；AF_XDP 流仍走 copy relay。

## TLS / HTTPS

- rustls crypto provider 切换为 **aws-lc-rs**（替换 ring）。
- 下游 accept 握手在无 cert callback 时 offload 到 `spawn_blocking`，降低 worker 线程 TLS CPU 占用。
- 禁用 HTTP/3 0-RTT（`max_early_data_size = 0`）。
- OCSP 分页拉取与证书 resolved-key 缓存；SNI 为空时 Auto verify 返回 true。
- 上游 TLS connector 缓存与 origin H3 连接池。

## CI

- Release workflow 将 Ubuntu apt 源固定到 `archive.ubuntu.com` / `ports.ubuntu.com`，避免 Azure mirror 超时导致构建挂起。

## 升级说明

- **无自动数据迁移**：从 1.2.0 升级后，旧 `metrics.db` 和 `blocked_ips.json` 都不会被读取；历史本地 metrics 与旧 JSON 封禁需视为冷启动。Mace 里已有的 `FWBLK_V1_*` 记录仍会恢复。
- 若同一数据目录被多个进程占用，Mace 打开失败时 metrics 存储会降级为不可用（与旧版行为一致，日志会提示）。

## 工具链与依赖

- Rust **1.96.0 → 1.97.1**（`rust-toolchain.toml`、Release CI）。
- 主要 crate 升至 crates.io 当前稳定版（tokio 1.53、rustls 0.23.43、maxminddb 0.30、smoltcp 0.14、xsk-rs 0.9 等）。
- `rand` 0.10、`aes-gcm` 0.11 API 适配。
