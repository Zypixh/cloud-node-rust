## 1. 先接受最新工作约束

- 本机只读写源码、文档和文本证据，执行传输与远端操作。**禁止在 Mac 上编译、检查、运行测试或压测**，包括 `cargo check/build/test`、直接 `rustc`、eBPF 构建以及本机 OrbStack/其他 VM。构建产物留在 VPS，不再复制回本机 `data/`。
- 两台已授权 VPS：`vps-120` 与 `vps-110`（公网地址见仓库外凭据文件，不入库），各 2 CPU / 2 GB RAM；仅用于隔离的构建和测试。先核实系统、磁盘、权限与现有工作负载，再确定角色和资源上限。用户名暂按 `root` 验证。
- SSH 凭据已在本会话前一条接管指令指定的仓库外私密文件中；也可通过 `EDGE_DEV_CREDENTIALS_FILE` 指定该文件。用程序读取，不回显，不放入 shell 参数、Git、构建包或证据。目录 0700、文件 0600。使用独立 known_hosts；首次连接记录指纹，后续严格核对。
- 用户已授权清理本机本项目可再生 Rust 缓存和构建产物，包括 XDP。先核实路径，保留源码、工具链、配置和现有未提交更改。不得笼统删除 `~/.cargo`、`~/.rustup` 或其他项目目录。
- 不覆盖 VPS 既有业务；XDP、注流、压力和故障实验只操作本任务创建的 netns/veth/隔离测试接口，不挂载生产网卡，不改 SSH、防火墙、生产路由或服务。公开网络不作为压力测试路径。
- 同一工作树只有一个实现者。不要另开并行 Devin 写同一仓库，不启动旧 OrbStack 构建。所有源代码修改在本机完成，远端不独立修改形成第二份源码。
- 按阶段自主继续到所有当前可执行工作完成。遇到外部硬件限制，记录未验收条件并推进独立任务；涉及真实上线或确实缺少必要输入时才停下。本轮不自动部署、push 或 merge。

这组最新用户约束覆盖旧会话中的构建地点、任务调度方式与自动启动方式；原架构的安全不变量、依赖和验收门槛继续有效。

## 4. M0 的具体交付

### 4.1 清理本机

先检查本任务是否仍有旧编译进程，只停止确定属于本任务的旧构建。盘点根及嵌套 `target/`、配置/环境中自定义 target、`data/cloud-node-xdp-ebpf.o` 与其他经核实的 eBPF 生成对象，以及可安全清理的编译缓存和 Cargo 下载缓存。

每个路径记录清理前实际占用、是否 Git 跟踪、是否由本项目生成及删除结果，再计算释放空间。确认是生成产物后直接清理，不用可能触发工具链安装的 Cargo 命令。共享缓存有其他进程正在使用时先跳过并记录，不破坏其他任务。若清理 Git 跟踪的生成对象，明确记录删除及远端生成替代方式。

将清单写入 `docs/edge-node-evidence/VPS-MIGRATION/local-cleanup.md`。未清理项必须写明，不能只报一个估算总数。

### 4.2 两台机器的角色与资源

默认 `.120` 承担用户态构建、Rust 回归；`.110` 承担 eBPF 构建/verifier 与 netns/veth 功能验证。以实际空间和工具链调整角色，并记录。两机都要完成连通与能力盘点；不为形式上“两机验证”重复完整构建。

每台先记录 OS、内核、CPU、RAM、swap、可用磁盘、已有服务、BPF/netns 能力和工具链版本。在确认不冲突的新目录中工作，使用独立构建缓存与日志。每台最多一个 Cargo 构建进程，`CARGO_BUILD_JOBS=1`；优先关闭开发验证的 debuginfo，并对 RSS、swap、磁盘留量设预算。优先用有上限的 cgroup/进程资源约束。出现 OOM 或磁盘紧张先停止当前任务并调整，不无限重试。

如确需 swap，先核实磁盘和既有负载，再采用有大小上限、可清理的任务方案并记录；不贸然修改全机性能配置。小内存验证 profile 与正式 release profile 分开记录，不能用降低优化/LTO后的数据证明正式版本性能。

### 4.3 可重复同步与验证

交付仓库脚本/说明，实现“本机准备源码清单 → 上传 → 远端构建/测试 → 回收文本证据”。脚本需显式指定获授权主机及隔离目录；测试脚本拒绝非获授权主机与生产接口。本机入口应拒绝运行编译/测试阶段，不依赖操作者记忆。

源代码包含 dirty/untracked 的必要文件；排除 `.git`、本机产物、凭据与真实运行数据，保留构建需要的非敏感文件及 fixtures。不对未知目录执行 `rsync --delete`；已有目录先验证任务所有权，清理仅限该目录的已记录生成项。

对源码清单内容计算摘要，包含尚未跟踪的源文件；记录提交、dirty 状态、工具链、构建选项、配置/ABI、目标架构。证据和构建产物不计入自身摘要。同步后核对远端摘要，执行现有仓库构建和相关测试入口，保留真实命令与退出码。

在远端先验证用户态与 eBPF 基线，再运行隔离环境可支持的现有 smoke/probe。XDP verifier 或某种 attach 模式不受内核支持时记录限制和错误，不能用普通 Rust 单测冒充。不得把 `.o`、二进制或 target 目录下载回 Mac；后续部署需要时直接从远端受控产物获取。

交付 `docs/edge-node-evidence/VPS-MIGRATION/report.md`、`manifest.json`、两机环境摘要、源码摘要、远端日志位置及可复现操作说明。

## 5. 各阶段必须守住的设计与验收点

- **XDP 准入**：服务作用域独立于 XSK readiness；聚合预算先于高基数建表；per-CPU 额度总和受整机上限约束；畸形包与分片处理不得让无法完成的流继续消耗状态。命中 tuple、收到 SYN/UDP 首包不能直接升级为可信。
- **连接状态**：pending 绝对 TTL；明确单调时间、owner/epoch/incarnation；关闭、超时、重用 tuple、旧事件、map 满和队列满都不能产生错误晋级或泄漏。合法存量流不能被随机驱逐以换取攻击包准入。
- **TCP 强验证**：分别说明 kernel、NAT、AF_XDP 的握手所有者、状态导入和序号处理。cookie 数学验证只是一个环节；第三 ACK 携带数据、MSS/window/timestamp/ECN、重传、密钥轮换和响应预算需要端到端证据。未实现的路径显式标为有限准入，不能静默换承载。
- **QUIC/UDP**：终止型 QUIC 依据锁定 Quinn API 处理 Retry、`may_retry` 和地址验证；透传不伪装为终止端注入 Retry。迁移/CID 不能绕过预算，也不能把合法连接因 tuple 改变直接杀掉；响应遵守防放大约束。
- **AF_XDP**：XSK 必须匹配入站 netdev/RX queue；fill/TX completion/UMEM 只有明确所有者；增加队列不扩大整机预算；过载/worker 失效有明确服务故障合同，不任意 PASS，也不把活跃 smoltcp TCP 透明迁移给内核。
- **代理与缓存**：身份和租户隔离先于缓存复用；WAF 有时间/字节/工作量上限；回源重试与并发 fill 有预算；purge 能挡住内存 HIT、旧 fill 和重启后复活；持久化定义 fsync/恢复顺序，不能只以 rename 作为完成证明。
- **运行可靠性**：配置跨组件代次一致；发布失败保留 LKG；排空尊重状态所有者；计费区分尝试、接受与交付；指标本身有成本上限；内存/FD/队列/磁盘压力都验证恢复与残留资源。

每个里程碑先完成必要实现和针对性远端验证，再推进下一项。测试优先覆盖真实失败反例，避免只镜像实现的测试。正常业务、混合攻击、资源耗尽、重载/崩溃恢复要按任务卡逐步进入，不能只测攻击丢包计数。

## 6. 能证明什么，不能证明什么

这两台 2c2g VPS 适合验证编译、verifier、隔离网络中的协议正确性、有界资源、故障与小规模混合负载。记录并控制生成器消耗；同机生成器与被测进程争用 CPU 时，吞吐是该测试环境结果。

它们不能自动证明真实 NIC 的 zero-copy、RSS/NUMA、多队列线速、10/100G 容量或全球 DDoS 缓解能力。即使 guest 内 XDP 正常丢包，入站链路和宿主机/vNIC 也可能先饱和。EN-31～33 必须明确外部硬件、上游带宽与运行环境前提；未测试的 profile 不获得生产资格。
